# 17. Records

Records (Java 16+) are Java's answer to C#'s `record` types — immutable data carriers with auto-generated boilerplate.

```java
// Compact declaration — generates constructor, getters, equals, hashCode, toString
public record Point(int x, int y) { }

// Usage
Point p = new Point(3, 4);
int x = p.x();      // accessor method (NOT .x — it's a method!)
int y = p.y();

// Records can have:
public record Person(String name, int age) {
    // Compact constructor (validation)
    public Person {
        if (age < 0) throw new IllegalArgumentException("Age cannot be negative");
        name = name.strip();  // can reassign parameters in compact constructor
    }

    // Additional constructor
    public Person(String name) {
        this(name, 0);
    }

    // Additional methods
    public String greeting() {
        return "Hello, I'm " + name;
    }

    // Static fields and methods
    public static final Person UNKNOWN = new Person("Unknown", 0);
}

// Records can implement interfaces
public record Range(int start, int end) implements Comparable<Range> {
    @Override
    public int compareTo(Range other) {
        return Integer.compare(this.start, other.start);
    }
}
```

**Comparison with C# records:**
- Java records: accessor methods are `name()`, not `Name` property
- Java records: no `with` expression (you must create a new instance manually)
- Java records: cannot extend classes (implicitly extend `java.lang.Record`)
- Java records: can implement interfaces
- Both: immutable by default, auto-generate equals/hashCode/toString
