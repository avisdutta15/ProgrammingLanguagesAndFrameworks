### Copy Constructor

Java has no built-in copy syntax like C#'s `with` expression or C++'s copy constructor. You write it manually.

```java
public class Address {
    private String street;
    private String city;
    private String zip;

    // Normal constructor
    public Address(String street, String city, String zip) {
        this.street = street;
        this.city = city;
        this.zip = zip;
    }

    // Copy constructor — takes an instance of the same class
    public Address(Address other) {
        this.street = other.street;
        this.city = other.city;
        this.zip = other.zip;
    }
}

public class Person {
    private String name;
    private int age;
    private Address address;  // reference type field

    public Person(String name, int age, Address address) {
        this.name = name;
        this.age = age;
        this.address = address;
    }

    // Shallow copy constructor — copies references as-is
    public Person(Person other) {
        this.name = other.name;
        this.age = other.age;
        this.address = other.address;  // ⚠️ same Address object shared!
        //for deep copy using copy constructor use the following
        //this.address = new Address(other.address);
    }

    // Deep copy constructor — creates independent copies of mutable fields
    public static Person deepCopy(Person other) {
        return new Person(
            other.name,      // String is immutable — safe to share
            other.age,       // primitive — copied by value
            new Address(other.address)  // new Address via its copy constructor
        );
    }
}
```

**Usage:**
```java
Address addr = new Address("123 Main St", "Springfield", "62701");
Person original = new Person("Alice", 30, addr);

// Shallow copy
Person shallow = new Person(original);
shallow.getAddress().setCity("Shelbyville");  // ⚠️ changes original too!
System.out.println(original.getAddress().getCity());  // "Shelbyville"

// Deep copy
Person deep = Person.deepCopy(original);
deep.getAddress().setCity("Capital City");    // independent
System.out.println(original.getAddress().getCity());  // "Shelbyville" (unchanged)
```

### Shallow Copy vs Deep Copy

| | Shallow Copy | Deep Copy |
|--|-------------|-----------|
| Primitives | Copied (independent) | Copied (independent) |
| Immutable objects (`String`, `Integer`) | Shared reference (safe — can't mutate) | Shared reference (same — no need to duplicate) |
| Mutable objects | Shared reference (⚠️ dangerous!) | New independent copy created |
| Performance | Fast | Slower (more allocations) |
| Independence | Partial — mutable fields are linked | Full — completely independent object graph |

#### Visual Comparison

```
SHALLOW COPY:
original.name ──────► "Alice"  ◄────── copy.name       (safe — String is immutable)
original.address ───► [Address] ◄───── copy.address     (⚠️ shared mutable object!)

DEEP COPY:
original.name ──────► "Alice"  ◄────── copy.name       (shared, but immutable = safe)
original.address ───► [Address A]                       (independent)
copy.address ───────► [Address B]                       (independent)
```

#### Implementing Deep Copy — Approaches

**1. Copy constructors (recommended for most cases):**
```java
// Already shown above — explicit, clear, type-safe
Person copy = new Person(original);  // or Person.deepCopy(original)
```

**2. Cloneable interface (legacy, not recommended):**
```java
public class Person implements Cloneable {
    @Override
    public Person clone() {
        try {
            Person copy = (Person) super.clone();  // shallow clone
            copy.address = new Address(this.address);  // fix mutable fields
            return copy;
        } catch (CloneNotSupportedException e) {
            throw new AssertionError();  // shouldn't happen
        }
    }
}
```
> `Cloneable` is considered a broken API in Java (Joshua Bloch's *Effective Java* calls it one of Java's biggest mistakes). Prefer copy constructors or static factory methods.

**3. Serialization (brute-force deep copy):**
```java
// Serialize to bytes, then deserialize — creates a completely independent copy
// Only works if all objects in the graph are Serializable
public static <T extends Serializable> T deepCopy(T obj) {
    try {
        ByteArrayOutputStream bos = new ByteArrayOutputStream();
        new ObjectOutputStream(bos).writeObject(obj);
        ByteArrayInputStream bis = new ByteArrayInputStream(bos.toByteArray());
        return (T) new ObjectInputStream(bis).readObject();
    } catch (Exception e) {
        throw new RuntimeException(e);
    }
}
```

**4. Records (Java 16+) — immutability sidesteps the problem:**
```java
// If your data is in records with only immutable fields, copying is trivial
// and shallow copy IS deep copy because nothing is mutable
public record Point(int x, int y) {}
public record Line(Point start, Point end) {}

Line original = new Line(new Point(0, 0), new Point(5, 5));
// No need to "deep copy" — records are immutable, shared references are safe
```

#### C# Comparison

| Concept | C# | Java |
|---------|-----|------|
| Shallow copy | `MemberwiseClone()` | `super.clone()` (via `Cloneable`) |
| Deep copy | `ICloneable` / copy constructor | Copy constructor / static factory |
| Record copy with modification | `person with { Name = "Bob" }` | Manual — no `with` expression |
| Immutable by default | `record` types | `record` types (Java 16+) |
