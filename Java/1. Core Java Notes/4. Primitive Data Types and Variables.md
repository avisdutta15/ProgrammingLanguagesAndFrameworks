# 4. Primitive Data Types and Variables

### Primitive Types

Java has 8 primitive types (value types). Unlike C#, these are NOT objects.

| Type | Size | Range | C# Equivalent |
|------|------|-------|---------------|
| `byte` | 8-bit signed | -128 to 127 | `sbyte` |
| `short` | 16-bit signed | -32,768 to 32,767 | `short` |
| `int` | 32-bit signed | -2³¹ to 2³¹-1 | `int` |
| `long` | 64-bit signed | -2⁶³ to 2⁶³-1 | `long` |
| `float` | 32-bit IEEE 754 | ~6-7 decimal digits | `float` |
| `double` | 64-bit IEEE 754 | ~15 decimal digits | `double` |
| `char` | 16-bit Unicode | '\u0000' to '\uffff' | `char` |
| `boolean` | JVM-dependent | `true` / `false` | `bool` |

**No unsigned types!** Java has no `uint`, `ulong`, etc. This is a notable omission compared to C#.

**No `decimal` type!** Use `java.math.BigDecimal` for financial calculations.

### Variable Declaration

```java
// Type inference with 'var' (since Java 10) — like C# var
var name = "Alice";          // inferred as String
var count = 42;              // inferred as int
var prices = new ArrayList<Double>(); // inferred as ArrayList<Double>

// Explicit typing
String name = "Alice";
int count = 42;
final double PI = 3.14159;  // 'final' = 'readonly' for local vars
```

### Type Casting

#### 1. Implicit (Widening) Casting

Automatic conversion from a smaller to a larger type. No data loss, no cast operator needed.

```
byte → short → int → long → float → double
         char → int
```

```java
byte b = 42;
int i = b;       // byte → int (automatic)
long l = i;      // int → long (automatic)
double d = l;    // long → double (automatic)

char c = 'A';
int code = c;    // char → int (65, automatic)
```

#### 2. Explicit (Narrowing) Casting

Manual conversion from a larger to a smaller type. Requires a cast operator — the compiler won't allow it otherwise because data may be lost.

```java
double d = 9.78;
int i = (int) d;       // compile error without (int)

long big = 100_000L;
int small = (int) big; // explicit cast required

int num = 65;
char c = (char) num;   // int → char: 'A'
```

#### 3. Truncating Casting

When narrowing, Java silently truncates — it chops off bits or decimal portions without rounding or throwing an error.

```java
// Decimal truncation (fractional part discarded, NOT rounded)
double price = 9.99;
int rounded = (int) price;   // 9, not 10

// Overflow truncation (high-order bits discarded)
int large = 130;
byte b = (byte) large;       // -126 (wraps around — 130 overflows byte's -128..127)

long huge = 3_000_000_000L;
int truncated = (int) huge;  // -1294967296 (upper 32 bits lost)

// float → int truncation
float f = Float.MAX_VALUE;
int i = (int) f;             // Integer.MAX_VALUE (clamped, not wrapped)
```

**Tip:** If you need rounding instead of truncation, use `Math.round()`:
```java
double d = 9.78;
int rounded = (int) Math.round(d);  // 10
```

#### 4. Boolean — No Casting Possible

`boolean` cannot be cast to or from any other type. There is no numeric representation of `true`/`false` in Java (unlike C/C++ where 0/1 works).

```java
boolean flag = true;

// ALL of these are compile errors:
int i = (int) flag;          // ❌ cannot cast boolean to int
boolean b = (boolean) 1;     // ❌ cannot cast int to boolean
char c = (char) flag;        // ❌ cannot cast boolean to char
double d = (double) flag;    // ❌ cannot cast boolean to double

// Workarounds if you need conversions:
int i = flag ? 1 : 0;              // boolean → int (manual)
boolean b = (i != 0);              // int → boolean (manual)
String s = String.valueOf(flag);   // "true" / "false"
boolean parsed = Boolean.parseBoolean("true");  // String → boolean
```

**C# comparison:** C# also forbids direct boolean-to-numeric casts, so this behavior is consistent across both languages.
