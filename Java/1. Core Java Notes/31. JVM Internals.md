# 34. JVM Internals

### Class Loading

```
Bootstrap ClassLoader → loads java.base module (rt.jar)
    ↓
Platform ClassLoader → loads platform modules
    ↓
Application ClassLoader → loads application classpath
    ↓
Custom ClassLoaders → user-defined loading strategies
```

```java
// Get classloader
ClassLoader cl = MyClass.class.getClassLoader();

// Load class dynamically
Class<?> clazz = Class.forName("com.example.MyClass");
Class<?> clazz2 = classLoader.loadClass("com.example.MyClass");
```

### JIT Compilation

The JVM uses Just-In-Time compilation:
1. Bytecode is initially interpreted
2. Hot methods are compiled to native code by C1 (quick) then C2 (optimized) compiler
3. Aggressive optimizations: inlining, loop unrolling, escape analysis, dead code elimination

### Key JVM Concepts

- **String Pool** — string literals are interned (shared) automatically
- **Escape Analysis** — objects that don't "escape" a method may be stack-allocated
- **Method Inlining** — small methods are inlined at call sites
- **Tiered Compilation** — interpreter → C1 (fast) → C2 (optimized)

### Useful JVM Tools

```bash
jps           # list Java processes
jstack <pid>  # thread dump
jmap <pid>    # memory map
jconsole      # graphical monitoring
jfr           # Java Flight Recorder (profiling)
javap -c      # disassemble bytecode
```
