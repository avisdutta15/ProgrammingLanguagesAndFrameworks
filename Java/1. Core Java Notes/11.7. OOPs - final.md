### The `final` Keyword

`final` means "cannot be changed after initialization." It applies to variables, methods, and classes — each with different meaning:

#### Final Variables (Constants)

Once assigned, the value cannot be changed:

```java
// Final local variable
final int x = 10;
x = 20;   // ❌ compile error: cannot assign a value to final variable

// Final field — must be initialized by the time constructor finishes
public class Circle {
    private final double radius;   // blank final — assigned in constructor

    public Circle(double radius) {
        this.radius = radius;      // ✓ assigned once in constructor
    }

    public void grow() {
        this.radius = 5.0;         // ❌ compile error: already assigned
    }
}

// Static final — class-level constant (convention: UPPER_SNAKE_CASE)
public static final double PI = 3.14159265358979;
public static final int MAX_RETRIES = 3;
```

#### Final with Reference Types — The Reference is Fixed, Not the Object!

```java
final List<String> names = new ArrayList<>();
names.add("Alice");     // ✓ modifying the LIST is fine
names.add("Bob");       // ✓ the object is mutable
names = new ArrayList<>();  // ❌ can't reassign the REFERENCE

final Person p = new Person("Alice");
p.setAge(31);           // ✓ mutating the object is fine
p = new Person("Bob");  // ❌ can't point 'p' to a different object
```

```
final List<String> names = ...

names ────────► [ArrayList: "Alice", "Bob"]   ← can modify contents
  │
  ✗ cannot reassign names to point elsewhere
```

**C# equivalent:** `readonly` for fields, no direct equivalent for local variables (C# doesn't have `final` for locals — but `const` exists for compile-time constants).

#### Final Methods — Cannot Be Overridden

Prevents subclasses from changing the method's behavior:

```java
public class Account {
    // No subclass can override this — security-critical logic
    public final void transfer(Account to, double amount) {
        validate(amount);
        this.balance -= amount;
        to.balance += amount;
        audit(this, to, amount);
    }
}

public class HackedAccount extends Account {
    @Override
    public void transfer(Account to, double amount) {  // ❌ compile error: cannot override final method
        // can't bypass validation/audit
    }
}
```

**When to use:** Security-critical methods, template method pattern (allow overriding hooks but not the algorithm itself).

#### Final Classes — Cannot Be Extended

No class can inherit from a final class:

```java
public final class String {
    // Nobody can extend String — ensures immutability guarantees can't be broken
}

public class MyString extends String {  // ❌ compile error: cannot inherit from final class
}
```

**Common final classes in Java:** `String`, `Integer`, `Double`, all wrapper classes, `Math`, `System`.

**Why?** Immutability and security. If someone could subclass `String`, they could override methods and break assumptions the JVM relies on.

#### Final Parameters

Method parameters declared `final` can't be reassigned inside the method (the object they reference can still be mutated):

```java
public void process(final String name, final List<String> items) {
    name = "other";       // ❌ can't reassign
    items = new ArrayList<>();  // ❌ can't reassign
    items.add("new item");     // ✓ can still mutate the object
}
```

Useful for clarity and to prevent accidental reassignment in long methods.

#### Summary: `final` in All Contexts

| Applied To | Meaning | C# Equivalent |
|-----------|---------|---------------|
| Local variable | Can't reassign after initialization | — (no direct equivalent) |
| Instance field | Must be assigned in constructor, can't change after | `readonly` |
| Static field | Class constant | `const` or `static readonly` |
| Method parameter | Can't reassign inside method | — (no equivalent) |
| Method | Can't be overridden by subclasses | `sealed` on method (C# default without `virtual`) |
| Class | Can't be extended (inherited from) | `sealed` on class |

#### `static final` — The Java Constant Pattern

```java
// Java's version of a constant (like C#'s const)
public static final int MAX_SIZE = 100;        // primitive — true compile-time constant
public static final String APP_NAME = "MyApp"; // String — also compile-time constant
public static final List<String> EMPTY = List.of();  // reference — not a compile-time constant (just immutable)
```

**Note:** Only primitives and `String` with `static final` are true compile-time constants (inlined by the compiler). Object references marked `static final` are runtime constants — the reference is fixed but determined at class-load time.
