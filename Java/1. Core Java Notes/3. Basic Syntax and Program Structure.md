# 3. Basic Syntax and Program Structure

### Hello World

```java
// File: HelloWorld.java
// In Java, the filename MUST match the public class name
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }
}
```

### Compiling and Running

```bash
# Compile -> Creates a HelloWorld.class file
javac HelloWorld.java

# Run
java HelloWorld

# Since Java 11 — single-file source-code execution
java HelloWorld.java
```

**C# comparison:** Very similar, but Java requires the file name to match the class name. No top-level statements (until Java 21 preview with unnamed classes).

- When we run the javac HelloWorld.java, the compiler transforms your human-readable .java source into .class bytecode that the JVM can execute.

- It's the intermediate format — not machine code, not source code, but something in between that the JVM interprets and JIT-compiles at runtime.

```
_1_HelloWorld.java  →  javac  →  _1_HelloWorld.class  →  java (JVM)  →  runs
    (source)                        (bytecode)
```
**C# comparison:** It's roughly equivalent to a .dll or .exe in C# — the compiled output you ship/deploy. You never edit .class files directly.

We cannot read the .class file. But if we open it using editors like VS Code (and IntelliJ), they will automatically decompile .class files back into readable Java.

### Since Java 21 — Simplified Main (Preview → Finalized in Java 25)

```java
// No class declaration needed
void main() {
    System.out.println("Hello, World!");
}
```

### Packages (Namespaces)

```java
// Packages are Java's equivalent of C# namespaces
package com.example.myapp;

// Import specific class
import java.util.List;

// Import all classes from a package (like 'using' with wildcard)
import java.util.*;

// Static import (like 'using static' in C#)
import static java.lang.Math.PI;
import static java.lang.Math.sqrt;
```

### Naming Conventions

| Element | Convention | Example |
|---------|-----------|---------|
| Package | all lowercase, reverse domain | `com.company.project` |
| Class | PascalCase | `CustomerOrder` |
| Method | camelCase | `calculateTotal()` |
| Variable | camelCase | `orderCount` |
| Constant | UPPER_SNAKE_CASE | `MAX_RETRY_COUNT` |
| Interface | PascalCase (no `I` prefix!) | `Serializable`, `Comparable` |

**Key difference from C#:** Java does NOT prefix interfaces with `I`. `List` is an interface, `ArrayList` is the implementation.

### Explain the signature of the `main` method in Java. Why is each keyword required?

```java
public static void main(String[] args)
```

| Keyword | Why it's required |
|---------|-------------------|
| `public` | The JVM calls `main` from outside the class. It must be accessible without restrictions. |
| `static` | The JVM invokes `main` without creating an instance of the class. No object exists yet at startup. |
| `void` | `main` returns nothing to the JVM. The exit code is set via `System.exit(int)` if needed. |
| `String[] args` | Receives command-line arguments as an array of strings. The parameter name can be anything (`args` is convention), but the type must be `String[]`. |

**Common follow-up questions:**

**Can we overload `main`?**
Yes, but the JVM only calls the `public static void main(String[] args)` signature as the entry point. Other overloads are just regular methods.

```java
public class App {
    public static void main(String[] args) {
        System.out.println("Entry point");
        main(42); // calling the overloaded version manually
    }

    public static void main(int num) {
        System.out.println("Overloaded: " + num); // not called by JVM
    }
}
```

**Can we declare `main` as `final`?**
Yes. `final` prevents subclasses from overriding it, but since `main` is `static`, it's hidden (not overridden) in subclasses anyway. It doesn't affect the JVM's ability to call it.

**Can we use `var-args` instead of `String[]`?**
Yes. `String... args` is valid since var-args are just syntactic sugar for arrays:

```java
public static void main(String... args) { } // works fine
```

**What happens if `main` is not `static`?**
The JVM throws `Error: Main method is not static`. It cannot call an instance method without an object, and no object exists before `main` runs.

**What about Java 21+ unnamed classes (JEP 463)?**
Since Java 21 (preview), you can write a simplified entry point without the full signature:

```java
// No class declaration, no String[] args needed
void main() {
    System.out.println("Hello");
}
```

This is a preview feature aimed at beginners and scripts. Production code still uses the traditional signature.
