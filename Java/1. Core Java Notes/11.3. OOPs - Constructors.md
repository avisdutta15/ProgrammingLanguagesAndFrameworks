### Constructors in Java

A constructor is a special method that initializes a new object. It has the same name as the class, no return type (not even `void`), and is called automatically when you use `new`.

```java
Person p = new Person("Alice", 30);
//         └── new ──┘ └── constructor call ──┘
```

**Rules:**
- Same name as the class
- No return type
- Called automatically on `new`
- Can be overloaded (multiple constructors with different params)
- Cannot be `abstract`, `static`, `final`, or `synchronized`

#### 1. Default Constructor (No-Arg)

Automatically provided by the compiler if you declare NO constructors. Takes no parameters, just calls `super()`:

```java
public class Person {
    private String name;
    // No constructor written → compiler inserts:
    // public Person() { super(); }
}

Person p = new Person();   // uses the compiler-generated default constructor
```

**Important:** The moment you write ANY constructor, the compiler stops providing the default one:

```java
public class Person {
    public Person(String name) { this.name = name; }
}

Person p = new Person();        // ❌ compile error — no no-arg constructor exists anymore!
Person p = new Person("Alice"); // ✓
```

#### 2. Parameterized Constructor

Takes one or more parameters — you define how to initialize the object:

```java
public class Person {
    private String name;
    private int age;

    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }
}

Person p = new Person("Alice", 30);
```

#### 3. Copy Constructor

Takes an instance of the same class and creates a duplicate (covered in detail in the next section):

```java
public class Person {
    private String name;
    private int age;

    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // Copy constructor
    public Person(Person other) {
        this.name = other.name;
        this.age = other.age;
    }
}

Person original = new Person("Alice", 30);
Person copy = new Person(original);   // new independent object with same values
```

#### Summary Table

| Type | Signature | Provided By | Use Case |
|------|-----------|-------------|----------|
| Default | `ClassName()` | Compiler (if no constructors declared) | Create object with defaults |
| Parameterized | `ClassName(params...)` | You | Initialize with specific values |
| Copy | `ClassName(ClassName other)` | You | Duplicate an existing object |

**Note:** Java has no destructor (like C++ `~ClassName()`). Cleanup is handled by the garbage collector. The `finalize()` method existed but is deprecated since Java 9 — use `try-with-resources` or `Cleaner` instead.

**C# comparison:** Same three types. C# also has `static` constructors (`static ClassName() { }`) — Java's equivalent is the `static { }` initializer block (not technically a constructor).

### Constructor Chaining, Overloading & `this`

#### The `this` Keyword

`this` refers to the current object instance — the object on which the method/constructor is being called:

```java
public class Person {
    private String name;
    private int age;

    public Person(String name, int age) {
        this.name = name;   // this.name = field, name = parameter
        this.age = age;     // resolves ambiguity when names collide
    }

    public Person getThis() {
        return this;   // return the current object (useful for method chaining)
    }
}
```

**When you need `this`:**
- Parameter name shadows a field → `this.name = name`
- Pass current object to another method → `someMethod(this)`
- Return current object for fluent API → `return this`
- Call another constructor → `this(...)` (see below)

#### Constructor Overloading

Multiple constructors with different parameter lists — same concept as method overloading:

```java
public class Person {
    private String name;
    private int age;
    private String email;

    // Full constructor
    public Person(String name, int age, String email) {
        this.name = name;
        this.age = age;
        this.email = email;
    }

    // Partial constructor — no email
    public Person(String name, int age) {
        this.name = name;
        this.age = age;
        this.email = "not provided";
    }

    // Minimal constructor — just name
    public Person(String name) {
        this.name = name;
        this.age = 0;
        this.email = "not provided";
    }

    // Default constructor — no args
    public Person() {
        this.name = "Unknown";
        this.age = 0;
        this.email = "not provided";
    }
}
```

**Problem:** Lots of duplication. If validation logic changes, you update 4 places. Fix → constructor chaining.

#### Constructor Chaining with `this(...)`

One constructor calls another using `this(...)` — eliminating duplication:

```java
public class Person {
    private String name;
    private int age;
    private String email;

    // Primary constructor — all logic lives here
    public Person(String name, int age, String email) {
        if (name == null || name.isBlank()) throw new IllegalArgumentException("Name required");
        if (age < 0) throw new IllegalArgumentException("Age can't be negative");
        this.name = name;
        this.age = age;
        this.email = email;
    }

    // Chains to primary — provides default email
    public Person(String name, int age) {
        this(name, age, "not provided");   // calls Person(String, int, String)
    }

    // Chains further — provides default age and email
    public Person(String name) {
        this(name, 0);   // calls Person(String, int) → which calls Person(String, int, String)
    }

    // Default — chains with all defaults
    public Person() {
        this("Unknown");   // calls Person(String) → Person(String, int) → Person(String, int, String)
    }
}
```

**Call chain:**
```
new Person()
    → this("Unknown")
        → this("Unknown", 0)
            → this("Unknown", 0, "not provided")   ← all validation happens HERE
```

#### Rules for `this(...)`

| Rule | Example |
|------|---------|
| Must be the FIRST statement | `this(name, 0);` before any other code |
| Can only call ONE other constructor | Can't do `this(...); this(...);` |
| Can't be mixed with `super(...)` | Either `this(...)` or `super(...)`, not both |
| No recursion | `this(...)` can't call itself (directly or indirectly) |

```java
public Person(String name) {
    System.out.println("hello");   // ❌ compile error — this() must be first
    this(name, 0);
}

public Person(String name) {
    this(name, 0);                 // ✓ first statement
    System.out.println("hello");   // ✓ code after this() is fine
}
```

#### Constructor Chaining with `super(...)`

When extending a class, `super(...)` calls the parent's constructor:

```java
public class Employee extends Person {
    private String department;

    public Employee(String name, int age, String email, String department) {
        super(name, age, email);   // calls Person(String, int, String)
        this.department = department;
    }

    public Employee(String name, String department) {
        super(name, 0, "not provided");   // calls parent's primary constructor
        this.department = department;
    }
}
```

**Rules:**
- `super(...)` must also be the first statement
- If you don't call `super(...)` explicitly, Java inserts `super()` (no-arg) automatically
- If parent has no no-arg constructor, you MUST call `super(...)` explicitly

#### Combining `this(...)` and `super(...)`

You can't use both in the same constructor, but you can chain `this(...)` calls that eventually call `super(...)`:

```java
public class Employee extends Person {
    private String department;

    // Primary — calls super
    public Employee(String name, int age, String email, String department) {
        super(name, age, email);           // ← this one calls parent
        this.department = department;
    }

    // Secondary — chains to primary via this(...)
    public Employee(String name, String department) {
        this(name, 0, "not provided", department);   // ← chains to above
    }
}
```

```
new Employee("Alice", "Engineering")
    → this("Alice", 0, "not provided", "Engineering")
        → super("Alice", 0, "not provided")    ← Person's constructor
        → this.department = "Engineering"
```

**C# comparison:**
| Java | C# |
|------|-----|
| `this(name, 0)` (first line inside body) | `: this(name, 0)` (after signature, before body) |
| `super(name, age)` (first line inside body) | `: base(name, age)` (after signature, before body) |

```csharp
// C# puts it after the signature:
public Person(string name) : this(name, 0) { }
public Employee(string name) : base(name, 0, "") { }
```
