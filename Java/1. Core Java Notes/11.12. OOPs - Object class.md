
### Objects in Java

#### The `Object` Class — Root of Everything

Every class in Java implicitly extends `java.lang.Object`. It's the ultimate parent — like C#'s `System.Object`. This means every object has these methods available:

```java
public class Object {
    public String toString() { ... }
    public boolean equals(Object obj) { ... }
    public int hashCode() { ... }
    public final Class<?> getClass() { ... }
    protected Object clone() { ... }
    public final void notify() { ... }
    public final void notifyAll() { ... }
    public final void wait() { ... }
    protected void finalize() { ... }   // deprecated since Java 9
}
```

#### `toString()` — String Representation

Default: `ClassName@hexHashCode`. Override to make it useful:

```java
public class Person {
    private String name;
    private int age;

    // Default toString() output: "Person@1a2b3c4d" — useless!

    @Override
    public String toString() {
        return "Person{name='%s', age=%d}".formatted(name, age);
    }
}

Person p = new Person("Alice", 30);
System.out.println(p);           // calls toString() → "Person{name='Alice', age=30}"
System.out.println("User: " + p); // string concatenation also calls toString()
```

**C# equivalent:** `object.ToString()` — same concept.

#### `equals()` — Logical Equality

Default: reference comparison (same as `==`). Override to compare field values:

```java
// Default behavior (inherited from Object):
Person a = new Person("Alice", 30);
Person b = new Person("Alice", 30);
a.equals(b);   // false! — default checks if same object in memory (a == b)

// After overriding:
@Override
public boolean equals(Object o) {
    if (this == o) return true;                        // same reference? equal
    if (o == null || getClass() != o.getClass()) return false;  // null or different type? not equal
    Person person = (Person) o;                        // safe cast
    return age == person.age && Objects.equals(name, person.name);  // compare fields
}

a.equals(b);   // true — same name and age
```

**The `equals()` contract (must follow all of these):**
- Reflexive: `x.equals(x)` → `true`
- Symmetric: `x.equals(y)` → `y.equals(x)`
- Transitive: `x.equals(y) && y.equals(z)` → `x.equals(z)`
- Consistent: same result every time (unless fields change)
- Null-safe: `x.equals(null)` → `false`

#### `hashCode()` — Hash for Collections

Returns an `int` used by hash-based collections (`HashMap`, `HashSet`). **If you override `equals()`, you MUST override `hashCode()`** — objects that are `equal()` must have the same hash code.

```java
@Override
public int hashCode() {
    return Objects.hash(name, age);   // utility that combines fields into a hash
}
```

**Why the contract matters:**

```java
Person p1 = new Person("Alice", 30);
Person p2 = new Person("Alice", 30);

// Without proper hashCode():
Set<Person> set = new HashSet<>();
set.add(p1);
set.contains(p2);   // false! — different hash → looks in wrong bucket → not found

// With proper hashCode():
set.contains(p2);   // true — same hash → same bucket → equals() confirms match
```

| Rule | Consequence |
|------|-------------|
| `a.equals(b)` → `a.hashCode() == b.hashCode()` | MUST hold (contract) |
| `a.hashCode() == b.hashCode()` → `a.equals(b)` | NOT necessarily (hash collisions are fine) |
| Override `equals()` without `hashCode()` | Broken `HashMap`/`HashSet` behavior |

#### `getClass()` — Runtime Type Information

```java
Person p = new Person("Alice", 30);
System.out.println(p.getClass());              // class com.example.Person
System.out.println(p.getClass().getName());    // com.example.Person
System.out.println(p.getClass().getSimpleName()); // Person
```

**C# equivalent:** `obj.GetType()`

#### Complete Example: Proper Object Implementation

```java
public class Person {
    private String name;
    private int age;

    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    @Override
    public String toString() {
        return "Person{name='%s', age=%d}".formatted(name, age);
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;
        Person person = (Person) o;
        return age == person.age && Objects.equals(name, person.name);
    }

    @Override
    public int hashCode() {
        return Objects.hash(name, age);
    }
}
```

**Tip:** IDEs (IntelliJ: Alt+Insert → equals/hashCode/toString) generate these for you. Or use `record` (Java 16+) which auto-generates all three.

#### Size of Objects in Memory

Java objects have overhead beyond their fields — the JVM adds metadata:

```
┌──────────────────────────────────────────────────────┐
│                    Object Header                      │
├──────────────────────────────────────────────────────┤
│  Mark Word (8 bytes)     — hash code, GC age, locks  │
│  Class Pointer (4 bytes) — pointer to Class metadata │
│  [Array Length (4 bytes) — only for arrays]           │
├──────────────────────────────────────────────────────┤
│                    Instance Fields                    │
│  (laid out by JVM with padding for alignment)        │
├──────────────────────────────────────────────────────┤
│                    Padding                            │
│  (to make total size a multiple of 8 bytes)          │
└──────────────────────────────────────────────────────┘
```

**Mark Word (8 bytes on 64-bit JVM):**

Stores runtime metadata that changes throughout the object's life. Its contents depend on the object's current state:

| Object State | Mark Word Contains |
|-------------|-------------------|
| Normal (unlocked) | Identity hash code (31 bits) + GC age (4 bits) + biased lock flag |
| Biased locked | Thread ID of the owning thread + epoch + GC age |
| Lightweight locked | Pointer to lock record on the owning thread's stack |
| Heavyweight locked (contended) | Pointer to the `ObjectMonitor` (mutex in native memory) |
| GC marked | Forwarding pointer (where the object moved during GC) |

```
Mark Word (64 bits) — unlocked state:
┌──────────────────┬────────┬────────┬────────────┬───────┐
│ unused (25 bits) │ hash   │ age    │ biased_lock│ lock  │
│                  │(31 bit)│(4 bit) │ (1 bit)    │(2 bit)│
└──────────────────┴────────┴────────┴────────────┴───────┘
```

- **Identity hash code:** Generated lazily on first `System.identityHashCode()` or `hashCode()` (if not overridden). Once computed, it's stored permanently — this is why a biased lock is revoked when `hashCode()` is called.
- **GC age:** How many garbage collections the object has survived (0-15). When it reaches the threshold (default 15), the object is promoted from Young Gen to Old Gen.
- **Lock bits:** Tell the JVM which locking state the object is in (unlocked, biased, lightweight, heavyweight).

**Class Pointer (4 bytes with compressed oops, 8 bytes without):**

Points to the object's class metadata in Metaspace — the `Klass` structure that stores:
- The class name and package
- Method table (vtable) — for virtual method dispatch
- Field layout information
- Interface table (itable)
- Superclass pointer

```java
Person p = new Person("Alice", 30);
// p's class pointer → Klass for Person → contains method table, field offsets, etc.
// This is how the JVM knows p.toString() should call Person.toString(), not Object.toString()
```

With compressed oops (default on 64-bit JVMs with <32GB heap), class pointers are 4 bytes instead of 8 — saving memory.

**Array Length (4 bytes — only for array objects):**

If the object is an array, an extra 4 bytes store the length. Regular objects don't have this field.

```java
int[] arr = new int[10];
// Header: Mark Word (8) + Class Pointer (4) + Array Length (4) = 16 bytes header
// Data:   10 × 4 bytes = 40 bytes
// Total:  56 bytes (16 header + 40 data, already multiple of 8 — no padding)

Object obj = new Object();
// Header: Mark Word (8) + Class Pointer (4) = 12 bytes header (no array length)
// Padding: 4 bytes to reach 16 (next multiple of 8)
// Total:  16 bytes
```

**Instance Fields (variable size):**

Your actual data — laid out by the JVM in a specific order for memory efficiency (not necessarily the order you declared them):

```java
public class Example {
    private long id;       // 8 bytes
    private int count;     // 4 bytes
    private boolean flag;  // 1 byte
    private char grade;    // 2 bytes
    private Object ref;    // 4 bytes (compressed reference) or 8 bytes
}
```

The JVM reorders fields to minimize gaps:
```
Actual layout (JVM may reorder):
 OFFSET  SIZE     FIELD
      0     8     (mark word)
      8     4     (class pointer)
     12     8     long id        ← longs/doubles first (8-byte aligned)
     20     4     int count      ← then ints (4-byte aligned)
     24     4     Object ref     ← then references (4-byte with compressed oops)
     28     2     char grade     ← then shorts/chars (2-byte aligned)
     30     1     boolean flag   ← then bytes/booleans (1-byte aligned)
     31     1     (padding)      ← pad to multiple of 8
     Total: 32 bytes
```

**Padding (0-7 bytes):**

The JVM pads objects so their total size is a multiple of 8 bytes. This is required for memory alignment — the CPU accesses aligned addresses faster, and the GC relies on it.

```java
// Example: class with one boolean field
public class Tiny { boolean flag; }

// Layout:
// Mark Word:      8 bytes
// Class Pointer:  4 bytes
// flag:           1 byte
// Subtotal:      13 bytes
// Padding:        3 bytes  ← pad to reach 16 (next multiple of 8)
// Total:         16 bytes  (even though you only need 1 byte of data!)
```

This is why `new Object()` is 16 bytes — the 12-byte header needs 4 bytes of padding to reach 16.

**Minimum object size:** 16 bytes (12 bytes header + 4 bytes padding) — even an empty class.

| Object | Approximate Size | Breakdown |
|--------|-----------------|-----------|
| `new Object()` | 16 bytes | 12 header + 4 padding |
| `new Integer(42)` | 16 bytes | 12 header + 4 (int field) |
| `new Long(42L)` | 24 bytes | 12 header + 8 (long field) + 4 padding |
| `new String("hi")` | ~48 bytes | header + byte[] reference + hash + coder + byte[] object |
| `int` (primitive) | 4 bytes | no object overhead |

**Why this matters:**
- `int` = 4 bytes vs `Integer` = 16 bytes (4x overhead!)
- An `int[1000]` ≈ 4016 bytes vs `Integer[1000]` ≈ 16,000+ bytes (each element is a separate object)
- This is why primitives exist and why `List<int>` isn't possible (would need value types — Project Valhalla)

#### Measuring Object Size

```java
// Using JOL (Java Object Layout) library — add to dependencies
// org.openjdk.jol:jol-core

import org.openjdk.jol.info.ClassLayout;

System.out.println(ClassLayout.parseInstance(new Person("Alice", 30)).toPrintable());
```

**Output (typical 64-bit JVM with compressed oops):**
```
Person object internals:
 OFFSET  SIZE   TYPE DESCRIPTION
      0     4        (object header - mark)
      4     4        (object header - class)
      8     4    int Person.age
     12     4 String Person.name (reference)
Instance size: 16 bytes
```

**C# comparison:** Similar — .NET objects have a header (sync block + method table pointer). `struct` in C# avoids this overhead; Java has no equivalent until Project Valhalla.
