# 6. Concurrent Collections

### ConcurrentHashMap

```java
import java.util.concurrent.ConcurrentHashMap;

ConcurrentHashMap<String, Integer> map = new ConcurrentHashMap<>();

// Atomic operations
map.put("key", 1);
map.putIfAbsent("key", 2);       // only if key not present
map.replace("key", 1, 10);       // CAS: if value==1, set to 10
map.remove("key", 10);           // remove only if value==10

// Atomic compute operations (Java 8+)
map.compute("hits", (k, v) -> (v == null) ? 1 : v + 1);
map.computeIfAbsent("cache", k -> expensiveCompute(k));
map.merge("score", 1, Integer::sum); // if absent: put(1), else: apply sum

// Bulk operations (Java 8+) — parallel with threshold
map.forEach(1000, (k, v) -> System.out.println(k + "=" + v));
long count = map.reduceValuesToLong(1000, Integer::longValue, 0L, Long::sum);
```

**ConcurrentHashMap internals (Java 8+):**
- Uses **CAS + synchronized on individual bins** (not segments like Java 7)
- Array of Nodes; first node in each bin is locked individually
- When bin exceeds 8 entries → converts to **red-black tree** (O(log n) lookup)
- `size()` uses a LongAdder-like distributed counter for scalability

### ConcurrentLinkedQueue / ConcurrentLinkedDeque

```java
import java.util.concurrent.ConcurrentLinkedQueue;

// Lock-free (CAS-based) unbounded queue
ConcurrentLinkedQueue<Task> queue = new ConcurrentLinkedQueue<>();
queue.offer(new Task("work"));
Task task = queue.poll(); // returns null if empty
```

### BlockingQueue Implementations

```java
import java.util.concurrent.*;

// ArrayBlockingQueue: bounded, array-backed, fair optional
BlockingQueue<String> abq = new ArrayBlockingQueue<>(100, true); // capacity=100, fair=true
abq.put("item");    // blocks if full
abq.take();         // blocks if empty
abq.offer("item", 1, TimeUnit.SECONDS); // blocks up to 1s

// LinkedBlockingQueue: optionally bounded, higher throughput (separate put/take locks)
BlockingQueue<String> lbq = new LinkedBlockingQueue<>(1000);

// PriorityBlockingQueue: unbounded, elements sorted by priority
BlockingQueue<Task> pbq = new PriorityBlockingQueue<>(11, Comparator.comparingInt(Task::priority));

// SynchronousQueue: zero-capacity — every put() must wait for a take()
BlockingQueue<String> sq = new SynchronousQueue<>();
// Used in Executors.newCachedThreadPool()

// DelayQueue: elements available only after their delay expires
BlockingQueue<DelayedTask> dq = new DelayQueue<>();

// LinkedTransferQueue (Java 7+): more efficient than SynchronousQueue for some patterns
TransferQueue<String> tq = new LinkedTransferQueue<>();
tq.transfer("item"); // blocks until a consumer receives it
tq.tryTransfer("item", 1, TimeUnit.SECONDS);
```

### CopyOnWriteArrayList

A thread-safe `List` where every write operation (add, set, remove) creates a fresh copy of the underlying array. Reads never block and never see a partially modified list.

#### How It Works

```
READ (frequent):  Just read the current array reference — no lock, no copy
WRITE (rare):     Lock → copy entire array → modify the copy → swap the reference
```

```java
CopyOnWriteArrayList<String> list = new CopyOnWriteArrayList<>();
list.add("Alice");    // locks, copies into new array, swaps reference
list.add("Bob");      // locks, copies ["Alice","Bob"] into new array, swaps reference

// Reads see a SNAPSHOT — no lock needed
String name = list.get(0);   // direct array access, zero overhead
```

#### Internal Structure

```
WRITE: list.add("Charlie")

Before:
list.array ──────► ["Alice", "Bob"]         ← all readers see this

During (writer holds lock):
list.array ──────► ["Alice", "Bob"]         ← readers still see this (unchanged)
new copy   ──────► ["Alice", "Bob", "Charlie"]  ← writer builds this

After (atomic reference swap):
list.array ──────► ["Alice", "Bob", "Charlie"]  ← readers now see this
(old array)        ["Alice", "Bob"]              ← garbage collected
```

#### Key Properties

| Aspect | Behavior |
|--------|----------|
| Reads | Lock-free, very fast — just array index access |
| Writes | Lock + full array copy — O(n) per write |
| Iterator | Snapshot — iterates over the array as it was when iterator was created |
| ConcurrentModificationException | Never — iterator works on a frozen snapshot |
| Best for | Read-heavy, write-rare scenarios (config lists, listener lists) |
| Worst for | Frequent writes or large lists (copying 10,000 elements on every add) |

#### Thread-Safe Iteration (No ConcurrentModificationException)

```java
CopyOnWriteArrayList<String> listeners = new CopyOnWriteArrayList<>();
listeners.add("Listener1");
listeners.add("Listener2");

// Thread 1: iterating
new Thread(() -> {
    for (String listener : listeners) {   // snapshot iterator — safe
        System.out.println(listener);
        try { Thread.sleep(100); } catch (InterruptedException e) {}
    }
}).start();

// Thread 2: modifying DURING iteration
new Thread(() -> {
    listeners.add("Listener3");           // doesn't affect Thread 1's iterator
    listeners.remove("Listener1");        // Thread 1 still sees "Listener1"
}).start();

// Thread 1 prints: Listener1, Listener2 (its snapshot — unaffected by writes)
```

With a regular `ArrayList`, this would throw `ConcurrentModificationException`.

#### When to Use

```java
// ✓ Good: event listeners (rarely modified, frequently iterated)
CopyOnWriteArrayList<EventListener> listeners = new CopyOnWriteArrayList<>();

// ✓ Good: configuration that's read by many threads but changed infrequently
CopyOnWriteArrayList<String> allowedHosts = new CopyOnWriteArrayList<>();

// ❌ Bad: frequently modified list
CopyOnWriteArrayList<Order> orders = new CopyOnWriteArrayList<>();  // terrible perf
// Use ConcurrentLinkedQueue or Collections.synchronizedList() instead
```

**C# equivalent:** No direct equivalent. Closest: `ImmutableList<T>` (System.Collections.Immutable) — similar philosophy but returns a new list on modification. Or manual `lock` + `List<T>.ToList()` for snapshot reads.
