# 1. Process vs Threads

### What is a Process?

A process is an independent program in execution with its own memory space (heap, stack, code, data segments). Each Java application runs as a separate process.

```java
// Each 'java MyApp' command creates a separate OS process
// Processes are isolated — one crashing doesn't affect others
```

| Aspect | Process | Thread |
|--------|---------|--------|
| Memory | Own address space (isolated) | Shares address space within a process |
| Communication | IPC (sockets, pipes, shared memory) — expensive | Direct access to shared variables — fast but dangerous |
| Creation cost | Heavy (OS allocates memory, resources) | Lightweight (shares process resources) |
| Crash impact | Isolated — one process crash doesn't kill others | Any thread crash kills the entire process |
| Context switch | Expensive (TLB flush, memory mapping) | Cheaper (same address space) |

```
┌─── Process A (java MyApp) ──────────────────────────┐
│  ┌──────────┐  ┌──────────┐  ┌──────────┐          │
│  │ Thread 1 │  │ Thread 2 │  │ Thread 3 │          │
│  │ (main)   │  │ (worker) │  │ (GC)     │          │
│  └──────────┘  └──────────┘  └──────────┘          │
│                                                      │
│  Shared: Heap, Code, Static Data                     │
│  Private per thread: Stack, Program Counter, Registers│
└──────────────────────────────────────────────────────┘

┌─── Process B (java AnotherApp) ─────────────────────┐
│  Completely isolated from Process A                   │
└──────────────────────────────────────────────────────┘
```

**C# equivalent:** Same concepts. `System.Diagnostics.Process` = Java's `ProcessBuilder`. Both .NET and Java threads are OS-level threads (until Java 21's virtual threads).

# 2. Concurrency vs Asynchronous vs Parallelism vs Multithreading

These terms are often confused. Here's the distinction:

| Concept | Definition | Analogy |
|---------|-----------|---------|
| **Concurrency** | Multiple tasks making progress (not necessarily simultaneously) | One chef switching between multiple dishes |
| **Parallelism** | Multiple tasks executing at the exact same time (requires multiple cores) | Multiple chefs each cooking a dish |
| **Multithreading** | Using multiple threads to achieve concurrency or parallelism | The mechanism — hiring more chefs |
| **Asynchronous** | Non-blocking execution — start a task and get notified when done | Order food delivery and do other things while waiting |

### How They Relate

```
Concurrency (broad concept)
├── Multithreading (one mechanism for concurrency)
│   ├── Parallelism (threads on multiple cores = true simultaneous execution)
│   └── Time-slicing (threads on single core = interleaved, not simultaneous)
└── Asynchronous (another mechanism — non-blocking I/O, event loops)
    └── Can use threads internally, or can be single-threaded (Node.js event loop)
```

### In Java Terms

| Concept | Java Implementation |
|---------|-------------------|
| Concurrency | `Thread`, `ExecutorService`, `synchronized` |
| Parallelism | `parallelStream()`, Fork/Join, multiple threads on multi-core |
| Multithreading | `Thread`, `Runnable`, `ExecutorService` |
| Asynchronous | `CompletableFuture`, NIO, callbacks |

### In .NET Terms (Comparison)

| .NET | Java | Notes |
|------|------|-------|
| `Thread` | `Thread` | Both are OS threads |
| `Task` (async/await) | `CompletableFuture` | Java has no language-level async/await |
| `Parallel.For` / `PLINQ` | `parallelStream()` / Fork/Join | Data parallelism |
| `ThreadPool` | `ExecutorService` | Thread pool management |
| `async`/`await` keywords | No equivalent keyword — use `.thenApply()` chains | Java relies on fluent API instead |
