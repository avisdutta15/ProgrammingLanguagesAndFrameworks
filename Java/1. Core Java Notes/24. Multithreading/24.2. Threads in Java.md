# 3. Threads in Java

### What is a Thread?

A thread is the smallest unit of execution within a process. Every Java application starts with a single thread — the **main thread**. Multithreading allows concurrent execution of two or more threads to maximize CPU utilization.

### Creating Threads

**Method 1: Extending Thread class**

```java
public class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println("Running in: " + Thread.currentThread().getName());
    }
}

// Usage
MyThread t = new MyThread();
t.start(); // start() creates a new OS thread; never call run() directly
```

**Method 2: Implementing Runnable (preferred — allows extending another class)**

```java
public class MyTask implements Runnable {
    @Override
    public void run() {
        System.out.println("Task running in: " + Thread.currentThread().getName());
    }
}

Thread t = new Thread(new MyTask(), "worker-1");
t.start();
```

**Method 3: Implementing Callable (returns a result, can throw checked exceptions)**

```java
Callable<Integer> task = () -> {
    Thread.sleep(1000);
    return 42;
};

ExecutorService executor = Executors.newSingleThreadExecutor();
Future<Integer> future = executor.submit(task);
System.out.println(future.get()); // blocks until result is available
executor.shutdown();
```

### Thread vs Runnable — The Relationship

`Thread` class **implements** the `Runnable` interface. And `Thread` has a constructor that accepts a `Runnable` object. This design creates two distinct approaches:

#### The Runnable Interface (from Java source)

```java
// java.lang.Runnable — a functional interface with a single method
@FunctionalInterface
public interface Runnable {
    void run();   // the task to execute — no return value, no checked exceptions
}
```

That's it — just one method. Any class that implements `Runnable` simply defines what work to do in `run()`.

#### The Thread Constructor (from Java source)

```java
// java.lang.Thread (simplified) — implements Runnable and accepts Runnable
public class Thread implements Runnable {
    private Runnable target;   // holds the task

    // Constructor that accepts a Runnable task
    public Thread(Runnable target) {
        this.target = target;
    }

    // Overloaded: Runnable + thread name
    public Thread(Runnable target, String name) {
        this.target = target;
        // sets the thread name
    }

    // start() — creates a new OS thread and calls run()
    public synchronized void start() {
        // ... native code to create OS thread ...
        // eventually calls this.run()
    }

    // run() — delegates to target if provided
    @Override
    public void run() {
        if (target != null) {
            target.run();   // calls YOUR Runnable's run()
        }
    }
}
```

This is why:

```
┌─────────────────────────────────────────────────────────────────────────┐
│                      «interface»                                         │
│                       Runnable                                           │
│                    ─────────────                                         │
│                    + run(): void                                         │
└────────────────────────┬────────────────────────────────────────────────┘
                         │ implements
                         │
┌────────────────────────▼────────────────────────────────────────────────┐
│                        Thread                                            │
│                    ─────────────                                         │
│  - target: Runnable              ← holds a reference to a Runnable      │
│                                                                          │
│  + Thread(Runnable target)       ← constructor accepts a Runnable       │
│  + start(): void                 ← creates OS thread, calls run()       │
│  + run(): void                   ← if target != null, calls target.run()│
└─────────────────────────────────────────────────────────────────────────┘
```

#### Approach 1: Extend Thread — You ARE the thread

When you extend `Thread`, your class **is** a thread. It has `start()` because it inherits it.

```java
public class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println("I am the thread AND the task");
    }
}

MyThread t = new MyThread();
t.start();   // ✓ works — MyThread IS a Thread, so it has start()
```

```
MyThread extends Thread
    │
    ▼
┌────────────────────┐
│ MyThread object    │ ← this IS a thread (has start(), run(), etc.)
│ - run() overridden │
│ - start() inherited│
└────────────────────┘
    │
    │ t.start()
    ▼
[New OS Thread Created] → calls t.run()
```

#### Approach 2: Implement Runnable — You ARE a task

When you implement `Runnable`, your class is just a **task** (a unit of work). It does NOT have `start()` — it needs a `Thread` to carry it.

```java
public class MyTask implements Runnable {
    @Override
    public void run() {
        System.out.println("I am just a task — I need a thread to run me");
    }
}

MyTask task = new MyTask();
// task.start();  // ❌ COMPILE ERROR — Runnable has no start() method!

Thread t = new Thread(task);  // wrap the task in a Thread
t.start();                     // ✓ now it runs
```

```
MyTask implements Runnable (just a task — no start())
    │
    │ passed to
    ▼
┌────────────────────────────┐
│ Thread object              │
│ - target = myTask          │ ← holds your Runnable
│ - start() available        │
└────────────────────────────┘
    │
    │ t.start()
    ▼
[New OS Thread Created] → calls thread.run() → calls target.run() → your MyTask.run()
```

#### What Thread.run() Actually Does

```java
// Simplified Thread.run() source code:
public class Thread implements Runnable {
    private Runnable target;   // the task passed via constructor

    public Thread(Runnable target) {
        this.target = target;
    }

    @Override
    public void run() {
        if (target != null) {
            target.run();      // delegates to the Runnable's run()
        }
        // if target is null (extended Thread), the overridden run() executes instead
    }
}
```

#### Why Runnable is Preferred

| | Extend `Thread` | Implement `Runnable` |
|--|-----------------|---------------------|
| Inheritance | Uses up your one `extends` slot | Free to extend another class |
| Separation of concerns | Thread IS the task (coupled) | Thread and task are separate (decoupled) |
| Reusability | Can't reuse the task with thread pools | Same Runnable can be submitted to any executor |
| Semantics | "I am a thread" | "I am a task that can run on any thread" |
| Thread pools | Doesn't work with `ExecutorService` | Works with `ExecutorService.submit(runnable)` |

```java
// Runnable works everywhere:
Runnable task = () -> System.out.println("Hello");

new Thread(task).start();                    // manual thread
executor.submit(task);                       // thread pool
scheduledExecutor.scheduleAtFixedRate(task, 0, 1, TimeUnit.SECONDS);  // scheduled
```

**Rule:** Always implement `Runnable` (or `Callable`) unless you have a specific reason to extend `Thread`. Define tasks, not threads.

### Why `start()` and Not `run()`?

`run()` is just a regular method. Calling `t.run()` executes the code **on the current thread** — like calling any other method. No new thread is created.

`start()` does two things:
1. Creates a new OS thread (via native JVM code)
2. That new OS thread then calls `run()`

```java
Thread t = new Thread(() -> System.out.println(Thread.currentThread().getName()));

t.run();    // prints "main" — runs on YOUR thread, no new thread created
t.start();  // prints "Thread-0" — runs on a NEW thread
```

#### What `start()` Actually Does (Underlying Code)

```java
// Simplified from OpenJDK source (java.lang.Thread):
public class Thread implements Runnable {
    private volatile int threadStatus = 0;  // 0 = NEW

    public synchronized void start() {
        // 1. Check state — can only start a NEW thread
        if (threadStatus != 0)
            throw new IllegalThreadStateException();  // can't start twice!

        // 2. Add to thread group
        group.add(this);

        // 3. Call native method — this is where the OS thread is created
        start0();   // ← native call to the JVM/OS
    }

    // Native method — implemented in C/C++ inside the JVM
    private native void start0();

    // run() — just a regular method, called BY the new OS thread
    @Override
    public void run() {
        if (target != null) {
            target.run();
        }
    }
}
```

#### What `start0()` Does at the JVM/OS Level

`start0()` is a JNI (Java Native Interface) call into the JVM's C++ code:

```c
// JVM C++ code (hotspot/src/share/vm/runtime/thread.cpp) — conceptual
void JVM_StartThread(Thread* java_thread) {
    // 1. Allocate OS thread stack
    // 2. Create OS thread (pthread_create on Linux, CreateThread on Windows)
    //    entry point = thread_entry
}

void thread_entry(Thread* java_thread) {
    // This runs ON THE NEW OS THREAD
    // Calls java_thread.run() ← your code finally executes here
}
```

#### The Full Picture

```
YOUR CODE                        JVM                           OS
─────────                    ─────────                    ──────────
t.start()
    │
    ├─► check state (must be NEW)
    ├─► start0()  ──────────►  JVM_StartThread()
    │                              │
    │                              ├─► allocate stack
    │                              ├─► pthread_create() ──────► OS creates thread
    │                              │                              │
    │                              │                              ▼
    │   (returns immediately)      │                     [New OS Thread Running]
    │                              │                              │
    ▼                              │                              ▼
 (continues on                     │                     thread_entry()
  main thread)                     │                              │
                                   │                              ▼
                                   │                     calls t.run()
                                   │                              │
                                   │                              ▼
                                   │                     YOUR run() code executes
                                   │                     on the NEW thread
```

#### Why `run()` Alone Doesn't Work

```java
t.run();   // This is just:
           // 1. Look up method run() in Thread object
           // 2. Execute it on the CALLING thread's stack
           // No OS thread, no stack allocation, no concurrency
           // Same as calling any method: t.toString(), t.hashCode(), etc.
```

`run()` has nothing special about it — it's a plain `public void` method. The magic is entirely in `start()` → `start0()` → OS thread creation → OS thread calls `run()`.

**C# equivalent:** Same design. `Thread.Start()` creates the OS thread; calling the delegate directly would just run it on the current thread.

### Daemon vs Non-Daemon Threads

```java
Thread daemon = new Thread(() -> {
    while (true) {
        // background work — JVM exits when only daemon threads remain
    }
});
daemon.setDaemon(true); // must be set BEFORE start()
daemon.start();
```

- **Non-daemon (user) threads**: JVM waits for all user threads to finish before exiting.
- **Daemon threads**: Background threads (GC, finalizer). JVM does NOT wait for them.

**C# equivalent:**
| .NET | Java | Notes |
|------|------|-------|
| Foreground thread (default) | Non-daemon thread (default) | App waits for these to finish |
| Background thread (`IsBackground = true`) | Daemon thread (`setDaemon(true)`) | App exits without waiting |
| Managed threads (.NET runtime) | JVM-managed threads | Both are wrappers around OS threads |

### Runnable as a Functional Interface — The Lambda Evolution

`Runnable` has existed since Java 1.0 — long before functional interfaces were formalized. It became a lambda target in Java 8 because it has exactly one abstract method:

```java
@FunctionalInterface
public interface Runnable {
    void run();   // () → void — takes nothing, returns nothing
}
```

This means all four styles below do the **exact same thing** — only the ceremony differs:

```java
// 1. Named class (Java 1.0)
class MyTask implements Runnable {
    public void run() {
        System.out.println("Running on: " + Thread.currentThread().getName());
    }
}
Thread t1 = new Thread(new MyTask());
t1.start();

// 2. Anonymous class (Java 1.1)
Thread t2 = new Thread(new Runnable() {
    @Override
    public void run() {
        System.out.println("Running on: " + Thread.currentThread().getName());
    }
});
t2.start();

// 3. Lambda (Java 8)
Thread t3 = new Thread(() -> {
    System.out.println("Running on: " + Thread.currentThread().getName());
});
t3.start();

// 4. One-liner
new Thread(() -> System.out.println("Hello from thread")).start();
```

#### How Thread Uses Runnable Under the Hood

```
┌─────────────────────────────────────────────────────────────┐
│  new Thread(runnable)                                       │
│      │                                                      │
│      ▼                                                      │
│  thread.start()                                             │
│      │                                                      │
│      ▼                                                      │
│  JVM creates a new OS thread                                │
│      │                                                      │
│      ▼                                                      │
│  JVM calls runnable.run() on the new thread                 │
│      │                                                      │
│      ▼                                                      │
│  Your lambda body executes                                  │
└─────────────────────────────────────────────────────────────┘
```

#### Runnable vs Callable

| | Runnable | Callable\<V\> |
|--|----------|---------------|
| Signature | `() → void` | `() → V` |
| Returns a value | No | Yes |
| Throws checked exceptions | No | Yes |
| Method | `run()` | `call()` |
| Used with | `Thread`, `ExecutorService` | `ExecutorService` only |

```java
// Runnable — no return value
Runnable task = () -> System.out.println("Done");
new Thread(task).start();

// Callable — returns a value, can throw checked exceptions
Callable<Integer> computation = () -> {
    Thread.sleep(1000);
    return 42;
};

ExecutorService executor = Executors.newSingleThreadExecutor();
Future<Integer> future = executor.submit(computation);
Integer result = future.get();   // blocks until complete, returns 42
executor.shutdown();
```

**Note:** `Thread` only accepts `Runnable`. If you need a return value, use `ExecutorService.submit(Callable)` instead.

#### Thread Factory Pattern with Lambdas

`ThreadFactory` is another functional interface — it creates threads with custom configuration:

```java
@FunctionalInterface
public interface ThreadFactory {
    Thread newThread(Runnable r);   // Runnable → Thread
}
```

Use it to customize threads created by executors:

```java
// Lambda-based ThreadFactory
ThreadFactory factory = runnable -> {
    Thread t = new Thread(runnable);
    t.setDaemon(true);
    t.setName("worker-" + t.getId());
    t.setPriority(Thread.MIN_PRIORITY);
    return t;
};

// Use with thread pools
ExecutorService executor = Executors.newFixedThreadPool(4, factory);
executor.submit(() -> System.out.println(Thread.currentThread().getName()));
// prints: worker-21 (or similar)
```

#### Common Functional Interfaces in Concurrency

| Interface | Signature | Used For |
|-----------|-----------|----------|
| `Runnable` | `() → void` | Tasks without return values |
| `Callable<V>` | `() → V` | Tasks that return a value |
| `ThreadFactory` | `Runnable → Thread` | Custom thread creation |
| `RejectedExecutionHandler` | `(Runnable, ThreadPoolExecutor) → void` | Handling rejected tasks |
| `ForkJoinPool.ForkJoinWorkerThreadFactory` | `ForkJoinPool → ForkJoinWorkerThread` | Custom fork-join threads |

## Thread Lifecycle and States

```
        start()
NEW ──────────► RUNNABLE ◄──────────────────────────────┐
                   │                                      │
                   │ scheduler picks                      │
                   ▼                                      │
               RUNNING                                    │
                   │                                      │
       ┌───────────┼───────────────┐                     │
       │           │               │                     │
       ▼           ▼               ▼                     │
   BLOCKED     WAITING      TIMED_WAITING                │
       │           │               │                     │
       └───────────┴───────────────┘─────────────────────┘
                   │
                   ▼
              TERMINATED
```

| State | Trigger |
|-------|---------|
| NEW | Thread object created, not yet started |
| RUNNABLE | `start()` called; ready to run or running |
| BLOCKED | Waiting to acquire a monitor lock |
| WAITING | `Object.wait()`, `Thread.join()`, `LockSupport.park()` |
| TIMED_WAITING | `Thread.sleep(ms)`, `wait(ms)`, `join(ms)` |
| TERMINATED | `run()` completed or exception thrown |

### How a Thread Transitions Between States

#### RUNNABLE → BLOCKED (Waiting for a Lock)

A thread enters BLOCKED when it tries to enter a `synchronized` block but another thread already holds that lock:

```java
Object lock = new Object();

Thread t1 = new Thread(() -> {
    synchronized (lock) {          // t1 acquires the lock
        try { Thread.sleep(5000); } catch (InterruptedException e) {}
    }
});

Thread t2 = new Thread(() -> {
    synchronized (lock) {          // t2 tries to acquire → BLOCKED until t1 releases
        System.out.println("t2 got the lock");
    }
});

t1.start();
Thread.sleep(100);   // ensure t1 gets the lock first
t2.start();
Thread.sleep(100);
System.out.println(t2.getState());  // BLOCKED — waiting for t1 to release lock
```

```
t1: RUNNABLE → acquires lock → sleeps (holds lock)
t2: RUNNABLE → tries to acquire lock → BLOCKED (lock is held by t1)
t1: releases lock → t2 becomes RUNNABLE → acquires lock
```

#### RUNNABLE → WAITING (Indefinite Wait)

A thread enters WAITING when it voluntarily gives up execution until another thread explicitly wakes it:

```java
// Example 1: Object.wait() — waits until notify()/notifyAll()
Object monitor = new Object();

Thread t1 = new Thread(() -> {
    synchronized (monitor) {
        try { monitor.wait(); }     // releases lock, enters WAITING
        catch (InterruptedException e) {}
        System.out.println("Woken up!");
    }
});

t1.start();
Thread.sleep(100);
System.out.println(t1.getState());  // WAITING

synchronized (monitor) {
    monitor.notify();               // wakes t1 → back to RUNNABLE
}
```

```java
// Example 2: Thread.join() — waits until the other thread finishes
Thread worker = new Thread(() -> {
    try { Thread.sleep(3000); } catch (InterruptedException e) {}
});

Thread waiter = new Thread(() -> {
    try { worker.join(); }          // WAITING until worker finishes
    catch (InterruptedException e) {}
    System.out.println("Worker finished!");
});

worker.start();
waiter.start();
Thread.sleep(100);
System.out.println(waiter.getState());  // WAITING — waiting for worker to die
```

```java
// Example 3: LockSupport.park() — waits until unpark()
Thread t = new Thread(() -> {
    LockSupport.park();             // WAITING until someone calls unpark(t)
    System.out.println("Unparked!");
});

t.start();
Thread.sleep(100);
System.out.println(t.getState());   // WAITING
LockSupport.unpark(t);              // wakes t → RUNNABLE
```

#### RUNNABLE → TIMED_WAITING (Wait with Timeout)

Same as WAITING but with a maximum duration — the thread wakes up automatically when the time expires (or earlier if explicitly woken):

```java
// Example 1: Thread.sleep(ms) — pauses for a fixed time
Thread t = new Thread(() -> {
    try { Thread.sleep(5000); }     // TIMED_WAITING for 5 seconds
    catch (InterruptedException e) {}
});

t.start();
Thread.sleep(100);
System.out.println(t.getState());   // TIMED_WAITING
```

```java
// Example 2: Object.wait(ms) — wait with timeout
Object monitor = new Object();

Thread t = new Thread(() -> {
    synchronized (monitor) {
        try { monitor.wait(3000); }  // TIMED_WAITING — wakes after 3s OR on notify()
        catch (InterruptedException e) {}
    }
});

t.start();
Thread.sleep(100);
System.out.println(t.getState());   // TIMED_WAITING
```

```java
// Example 3: Thread.join(ms) — wait for thread but with a deadline
Thread worker = new Thread(() -> {
    try { Thread.sleep(10000); } catch (InterruptedException e) {}
});

Thread waiter = new Thread(() -> {
    try { worker.join(2000); }       // TIMED_WAITING — gives up after 2s
    catch (InterruptedException e) {}
    System.out.println("Done waiting (worker may still be running)");
});

worker.start();
waiter.start();
Thread.sleep(100);
System.out.println(waiter.getState());  // TIMED_WAITING
```

#### Summary: What Causes Each Transition

| From | To | Triggered By | Returns To RUNNABLE When |
|------|----|-------------|--------------------------|
| RUNNABLE | BLOCKED | `synchronized` — lock held by another thread | Lock is released |
| RUNNABLE | WAITING | `wait()`, `join()`, `LockSupport.park()` | `notify()`, thread dies, `unpark()` |
| RUNNABLE | TIMED_WAITING | `sleep(ms)`, `wait(ms)`, `join(ms)`, `parkNanos()` | Timeout expires OR explicit wake-up |
| RUNNABLE | TERMINATED | `run()` completes or throws uncaught exception | — (final state) |

```java
Thread t = new Thread(() -> {});
System.out.println(t.getState()); // NEW
t.start();
System.out.println(t.getState()); // RUNNABLE (or TERMINATED if fast)
```

### Why You Can't Start a Thread Twice

A `Thread` object represents a **single OS thread lifecycle** — once that OS thread finishes (TERMINATED state), the resources are released and it can't be resurrected.

```java
Thread t = new Thread(() -> System.out.println("Hello"));
t.start();   // ✓ creates OS thread, runs, finishes → state = TERMINATED
t.start();   // ❌ IllegalThreadStateException
```

The check inside `start()`:

```java
public synchronized void start() {
    if (threadStatus != 0)    // 0 = NEW, anything else = already started or dead
        throw new IllegalThreadStateException();
    // ...
}
```

After `start()` is called, the state transitions NEW → RUNNABLE → TERMINATED — it never goes back to NEW.

**Why this makes sense:**
1. **OS resources are gone.** When an OS thread finishes, the kernel reclaims its stack, registers, and scheduling slot. You can't restart a dead OS thread — the OS doesn't support it.
2. **State becomes inconsistent.** If the thread modified shared state during its first run, restarting it might produce incorrect results.
3. **Thread identity.** A thread has an ID and a history (stack traces, profiling). Reusing the same object for a different OS thread would make debugging meaningless.

**What to do instead — create a new Thread or use a pool:**

```java
Runnable task = () -> System.out.println("Hello");

// Option 1: New Thread object, same task
new Thread(task).start();   // first run
new Thread(task).start();   // second run — new Thread, same logic

// Option 2: Thread pool — reuses OS threads internally
ExecutorService pool = Executors.newFixedThreadPool(4);
pool.submit(task);   // pool manages thread creation/reuse
pool.submit(task);   // same OS thread might execute both
```
