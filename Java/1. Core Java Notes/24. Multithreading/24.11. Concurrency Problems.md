# 11. Concurrency Problems

### Deadlock

```java
// Classic: Two threads acquire two locks in opposite order
Object lockA = new Object(), lockB = new Object();

// Thread 1:
synchronized (lockA) {       // holds A
    synchronized (lockB) {   // waits for B
        // ...
    }
}

// Thread 2:
synchronized (lockB) {       // holds B
    synchronized (lockA) {   // waits for A → DEADLOCK!
        // ...
    }
}

// Prevention: Always acquire locks in a consistent global order
// Or use tryLock with timeout:
if (lock1.tryLock(1, TimeUnit.SECONDS)) {
    try {
        if (lock2.tryLock(1, TimeUnit.SECONDS)) {
            try { /* work */ } finally { lock2.unlock(); }
        }
    } finally { lock1.unlock(); }
}
```

### Livelock

```java
// Both threads keep yielding to each other — making progress but never completing
public void politeWorker(Lock myLock, Lock otherLock) {
    while (true) {
        myLock.lock();
        if (!otherLock.tryLock()) {
            myLock.unlock();          // "After you!"
            Thread.yield();
            continue;                 // Both threads do this simultaneously → livelock
        }
        try { /* work */ break; }
        finally { otherLock.unlock(); myLock.unlock(); }
    }
}
// Fix: Add random backoff delay
```

### Starvation

A thread never gets CPU time because higher-priority threads monopolize the scheduler.
- Use fair locks: `new ReentrantLock(true)`
- Avoid `Thread.setPriority()` extremes

### False Sharing

```java
// Two threads update adjacent fields → they share a CPU cache line (64 bytes)
// Each update invalidates the other thread's cache line → performance collapse

public class FalseSharing {
    volatile long counter1; // cache line A
    volatile long counter2; // likely SAME cache line A → false sharing!
}

// Fix: Pad to separate cache lines
public class NoPadding {
    volatile long counter1;
    long p1, p2, p3, p4, p5, p6, p7; // 56 bytes padding
    volatile long counter2; // now in a different cache line
}

// Java 8+ annotation:
@jdk.internal.vm.annotation.Contended
volatile long counter1; // JVM adds padding automatically
// Requires: -XX:-RestrictContended
```

| Problem | Description | Java Solution Approach |
|---------|-------------|----------------------|
