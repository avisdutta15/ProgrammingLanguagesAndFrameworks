# 10. Java Memory Model and Happens-Before

The JMM defines when one thread's writes become visible to another thread.

### Happens-Before Rules (guarantee visibility)

| Rule | Description |
|------|-------------|
| Program order | Each action happens-before the next in the same thread |
| Monitor lock | Unlock happens-before subsequent lock on same monitor |
| Volatile | Write to volatile happens-before subsequent read of same variable |
| Thread start | `thread.start()` happens-before any action in the started thread |
| Thread join | All actions in a thread happen-before `join()` returns |
| Final fields | Writing a final field in constructor happens-before reading it (after construction) |
| Transitivity | If A happens-before B, and B happens-before C, then A happens-before C |

### Memory Barriers / Fences

```
┌─────────────────────────────────────────────────────┐
│              Thread's Working Memory                  │
│  (CPU registers, L1/L2 cache, store buffers)         │
│                                                      │
│  volatile write → StoreStore + StoreLoad barriers    │
│                   (flush to main memory)              │
│                                                      │
│  volatile read  → LoadLoad + LoadStore barriers      │
│                   (invalidate cache, read from main)  │
└──────────────────────┬──────────────────────────────┘
                       │ barriers force synchronization
                       ▼
┌─────────────────────────────────────────────────────┐
│                  Main Memory (Heap)                   │
└─────────────────────────────────────────────────────┘
```

### Dangerous Example Without Proper Synchronization

```java
public class Visibility {
    private int x = 0;
    private boolean ready = false; // NOT volatile!

    // Thread 1:
    public void writer() {
        x = 42;          // (1)
        ready = true;    // (2) — may be reordered BEFORE (1) by CPU/compiler!
    }

    // Thread 2:
    public void reader() {
        if (ready) {         // may see true...
            System.out.println(x); // ...but x might still be 0!
            // Without happens-before, no guarantee (1) is visible when (2) is visible
        }
    }
}

// Fix: make ready volatile
// volatile write at (2) happens-before volatile read in reader
// AND by program order (1) happens-before (2)
// Transitivity: (1) happens-before reader sees ready==true → x guaranteed 42
```
