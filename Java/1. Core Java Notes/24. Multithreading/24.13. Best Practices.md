# 13. Best Practices

### Thread Safety Decision Flowchart

```
Is the data shared between threads?
  │
  No ──► No synchronization needed
  │
  Yes
  │
  Is it read-only / immutable?
  │
  Yes ──► No synchronization needed (use final + immutable objects)
  │
  No (mutable shared state)
  │
  Is it a single variable/flag?
  │   │
  │   Yes ──► Is it only read/write (no compound operations)?
  │   │           │
  │   │        Yes ──► volatile
  │   │           │
  │   │        No (e.g., check-then-act, increment)
  │   │           │
  │   │        Low contention? ──► AtomicXxx
  │   │           │
  │   │        High contention? ──► LongAdder / LongAccumulator
  │   │
  │   No (multiple related variables or complex state)
  │       │
  │    Few writers? ──► ReadWriteLock / StampedLock
  │       │
  │    Simple critical section? ──► synchronized or ReentrantLock
  │       │
  │    Producer-consumer? ──► BlockingQueue
  │       │
  │    Map? ──► ConcurrentHashMap
```

### Guidelines

1. **Prefer immutability**: Immutable objects are inherently thread-safe.
2. **Minimize shared mutable state**: The less you share, the fewer concurrency issues.
3. **Use higher-level concurrency utilities** over wait/notify (use `java.util.concurrent`).
4. **Use thread pools** — never create raw threads for production workloads.
5. **Always release locks in `finally`** blocks.
6. **Prefer `Callable` + `Future`** over bare `Runnable` for tasks that produce results.
7. **Size thread pools correctly**:
   - CPU-bound: `N_threads = N_cores`  
   - I/O-bound: `N_threads = N_cores × (1 + wait_time / compute_time)`
8. **Avoid `Thread.stop()`, `suspend()`, `resume()`** — they're deprecated and unsafe.
9. **Handle `InterruptedException` properly**: Either re-throw or restore the interrupt flag.
   ```java
   try {
       Thread.sleep(1000);
   } catch (InterruptedException e) {
       Thread.currentThread().interrupt(); // restore flag
       return; // exit gracefully
   }
   ```
10. **Document thread-safety guarantees** in your classes using annotations like `@ThreadSafe`, `@NotThreadSafe`, `@GuardedBy("lock")`.

## Summary Table: Choosing the Right Tool

| Scenario | Recommended Tool |
|----------|-----------------|
| Simple flag/signal | `volatile boolean` |
| Atomic counter (low contention) | `AtomicInteger` / `AtomicLong` |
| Atomic counter (high contention) | `LongAdder` |
| Lock-free data structure | `AtomicReference` + CAS loop |
| Mutual exclusion (simple) | `synchronized` |
| Mutual exclusion (advanced) | `ReentrantLock` |
| Read-heavy shared data | `ReadWriteLock` / `StampedLock` |
| Thread-safe map | `ConcurrentHashMap` |
| Producer-consumer | `BlockingQueue` |
| Parallel decomposition | Fork/Join or parallel streams |
| Async pipeline | `CompletableFuture` |
| High-scale I/O concurrency | Virtual Threads (Java 21+) |
| Wait for N tasks to complete | `CountDownLatch` |
| Synchronize N threads per phase | `CyclicBarrier` / `Phaser` |
| Limit concurrent resource access | `Semaphore` |
