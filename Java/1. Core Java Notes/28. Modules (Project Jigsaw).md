# 31. Modules (Project Jigsaw)

The Java Platform Module System (JPMS), introduced in Java 9, provides strong encapsulation beyond packages. Similar in concept to .NET assemblies but more explicit.

### module-info.java

```java
// Located at the root of your source tree
module com.example.myapp {
    // Dependencies (like project references)
    requires java.base;           // implicitly required
    requires java.sql;
    requires java.net.http;
    requires transitive com.example.common;  // re-export dependency

    // Exported packages (public API)
    exports com.example.myapp.api;
    exports com.example.myapp.model;

    // Qualified exports (only to specific modules)
    exports com.example.myapp.internal to com.example.tests;

    // Open for reflection (needed for frameworks like Spring)
    opens com.example.myapp.model to com.fasterxml.jackson.databind;

    // Service provider interface
    uses com.example.spi.Plugin;
    provides com.example.spi.Plugin with com.example.myapp.MyPlugin;
}
```

### Key Benefits

- Strong encapsulation — non-exported packages are truly inaccessible
- Reliable configuration — missing dependencies detected at startup
- Smaller runtime images — only include needed modules (jlink)

### When to Use Modules

- Library authors: always (for strong API boundaries)
- Application developers: often skip it (use the "unnamed module" / classpath)
- Most frameworks (Spring, etc.) work without explicit modules
