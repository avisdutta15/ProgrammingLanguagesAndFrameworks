# 22. Exception Handling

### Exception Hierarchy

```
Throwable
├── Error (serious JVM problems — do not catch)
│   ├── OutOfMemoryError
│   ├── StackOverflowError
│   └── VirtualMachineError
└── Exception
    ├── RuntimeException (unchecked — like C# exceptions)
    │   ├── NullPointerException
    │   ├── IllegalArgumentException
    │   ├── IndexOutOfBoundsException
    │   ├── ClassCastException
    │   ├── UnsupportedOperationException
    │   └── ArithmeticException
    └── Checked Exceptions (MUST be caught or declared — no C# equivalent!)
        ├── IOException
        ├── SQLException
        ├── FileNotFoundException
        └── InterruptedException
```

### Checked vs Unchecked Exceptions (Critical Concept!)

**Checked exceptions** — the compiler FORCES you to handle them. You must either catch them or declare `throws` on your method. This is the most contentious feature difference from C#.

```java
// This will NOT compile — IOException is checked
public String readFile(String path) {
    return Files.readString(Path.of(path));  // COMPILE ERROR
}

// Option 1: Declare throws
public String readFile(String path) throws IOException {
    return Files.readString(Path.of(path));
}

// Option 2: Catch it
public String readFile(String path) {
    try {
        return Files.readString(Path.of(path));
    } catch (IOException e) {
        throw new RuntimeException("Failed to read file", e);
    }
}
```

### try-catch-finally

```java
try {
    // risky code
    int result = Integer.parseInt(input);
} catch (NumberFormatException e) {
    // handle specific exception
    System.err.println("Invalid number: " + e.getMessage());
} catch (IllegalArgumentException | NullPointerException e) {
    // multi-catch (Java 7+) — like C# 'when' filter but different
    System.err.println("Bad input: " + e.getMessage());
} catch (Exception e) {
    // catch-all
    e.printStackTrace();
} finally {
    // always runs (same as C#)
    cleanup();
}
```

### try-with-resources (like C#'s using statement)

```java
// AutoCloseable resources are automatically closed
try (var reader = new BufferedReader(new FileReader("file.txt"));
     var writer = new BufferedWriter(new FileWriter("out.txt"))) {
    String line;
    while ((line = reader.readLine()) != null) {
        writer.write(line);
        writer.newLine();
    }
}  // reader and writer are auto-closed here

// Any class implementing AutoCloseable or Closeable can be used
public class DatabaseConnection implements AutoCloseable {
    @Override
    public void close() {
        // cleanup
    }
}
```

### Throwing Exceptions

```java
// Throw new exception
throw new IllegalArgumentException("Value must be positive");

// Throw with cause (exception chaining)
try {
    // ...
} catch (SQLException e) {
    throw new DataAccessException("Query failed", e);
}

// Custom exceptions
public class InsufficientFundsException extends Exception {  // checked
    private final double amount;

    public InsufficientFundsException(double amount) {
        super("Insufficient funds: " + amount);
        this.amount = amount;
    }

    public double getAmount() {
        return amount;
    }
}

public class InvalidOrderException extends RuntimeException {  // unchecked
    public InvalidOrderException(String message) {
        super(message);
    }
}
```

### Best Practices

```java
// Prefer specific exceptions
catch (FileNotFoundException e)  // good
catch (Exception e)              // too broad

// Don't swallow exceptions
catch (Exception e) { }          // BAD — silent failure

// Use exception chaining
catch (IOException e) {
    throw new ServiceException("Read failed", e);  // preserves stack trace
}

// Effective use of NullPointerException message (Java 14+)
// JVM now tells you exactly what was null
// "Cannot invoke String.length() because the return value of getName() is null"
```
