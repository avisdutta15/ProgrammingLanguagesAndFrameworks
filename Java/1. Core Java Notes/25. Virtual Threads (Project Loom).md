# 27. Virtual Threads (Project Loom)

Virtual threads (Java 21+) are lightweight threads managed by the JVM — similar to C#'s async/await model but without the colored function problem.

```java
// Create virtual thread
Thread vThread = Thread.ofVirtual().start(() -> {
    System.out.println("Running on virtual thread");
});

// Virtual thread with name
Thread named = Thread.ofVirtual().name("worker-", 1).start(() -> { });

// Using ExecutorService with virtual threads
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    // Each submitted task gets its own virtual thread
    // Can handle millions of concurrent tasks
    IntStream.range(0, 100_000).forEach(i -> {
        executor.submit(() -> {
            Thread.sleep(Duration.ofSeconds(1));
            return i;
        });
    });
}

// Structured Concurrency (Preview in Java 21, evolving)
try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
    Subtask<String> user = scope.fork(() -> fetchUser());
    Subtask<List<Order>> orders = scope.fork(() -> fetchOrders());

    scope.join();           // wait for both
    scope.throwIfFailed();  // propagate errors

    return new UserProfile(user.get(), orders.get());
}
```

**Why virtual threads matter:**
- No need for reactive/async patterns for I/O-bound work
- Write blocking code that scales like async code
- 1 million+ concurrent virtual threads is normal
- No colored function problem (no async/await keywords needed)
- Blocking I/O calls automatically yield the carrier thread
