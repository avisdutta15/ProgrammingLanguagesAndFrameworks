## 10. Methods (Functions)

In Java, functions don't exist on their own — they always belong to a class. They're called **methods**. There are no global functions like in C or Python.

```java
public class MathUtils {
    // This is a method (Java's version of a function)
    public static int add(int a, int b) {
        return a + b;
    }
}

// Call it via the class
int result = MathUtils.add(3, 4);   // 7
```
---
### Pass by Value vs Pass by Reference

**Java is ALWAYS pass by value.** There is no pass by reference. But for objects, the value being passed is the reference (memory address) — which confuses many developers.

#### Primitives — Value is Copied

```java
public static void increment(int x) {
    x++;   // modifies local copy only
}

int a = 5;
increment(a);
System.out.println(a);   // still 5 — original unchanged
```

```
Before:  a = 5
Call:     x = 5   (copy of a's value)
Inside:  x = 6   (only x changes)
After:   a = 5   (a was never touched)
```

#### Objects — Reference is Copied (Not the Object!)

The reference (pointer) is copied, but both the original and the copy point to the same object on the heap:

```java
public static void rename(Person p) {
    p.setName("Bob");   // modifies the SAME object (via copied reference)
}

public static void reassign(Person p) {
    p = new Person("Charlie");   // reassigns LOCAL copy — caller unaffected
}

Person alice = new Person("Alice");

rename(alice);
System.out.println(alice.getName());   // "Bob" — object was mutated through the reference

reassign(alice);
System.out.println(alice.getName());   // still "Bob" — reassignment didn't propagate
```

```
rename(alice):
alice ──────► [ Person: "Alice" ]  ◄── p (copy of reference)
                    ↓ p.setName("Bob")
alice ──────► [ Person: "Bob" ]    ◄── p     (same object, mutated)

reassign(alice):
alice ──────► [ Person: "Bob" ]              (unchanged)
p ────────── ► [ Person: "Charlie" ]          (only local p changed)
```

### Passing Arrays (1D and 2D)

Arrays are objects in Java — so passing an array passes a copy of the reference. The method can modify the array's contents:

#### 1D Array

```java
public static void doubleAll(int[] arr) {
    for (int i = 0; i < arr.length; i++) {
        arr[i] *= 2;   // modifies the SAME array (reference was copied)
    }
}

int[] numbers = {1, 2, 3};
doubleAll(numbers);
System.out.println(Arrays.toString(numbers));   // [2, 4, 6] — modified!
```

#### 2D Array

```java
public static void fillRow(int[][] matrix, int row, int value) {
    Arrays.fill(matrix[row], value);   // modifies the same 2D array
}

int[][] grid = {{1, 2}, {3, 4}, {5, 6}};
fillRow(grid, 1, 99);
System.out.println(Arrays.deepToString(grid));   // [[1, 2], [99, 99], [5, 6]]
```

#### Reassigning the Array Reference Doesn't Affect Caller

```java
public static void replaceArray(int[] arr) {
    arr = new int[]{10, 20, 30};   // local reassignment — caller's reference unchanged
}

int[] original = {1, 2, 3};
replaceArray(original);
System.out.println(Arrays.toString(original));   // [1, 2, 3] — unchanged
```

### Passing Classes (Objects)

```java
public static void applyDiscount(Order order, double percent) {
    double discounted = order.getTotal() * (1 - percent / 100);
    order.setTotal(discounted);   // mutates the same Order object
}

Order myOrder = new Order(100.0);
applyDiscount(myOrder, 20);
System.out.println(myOrder.getTotal());   // 80.0 — modified through the reference
```

### Returning Multiple Values

Java methods return a single value. To return multiple values, use one of these approaches:

#### Option 1: Return an Array

```java
public static int[] minMax(int[] arr) {
    int min = Integer.MAX_VALUE, max = Integer.MIN_VALUE;
    for (int n : arr) {
        min = Math.min(min, n);
        max = Math.max(max, n);
    }
    return new int[]{min, max};   // return 2 values as array
}

int[] result = minMax(new int[]{3, 1, 7, 2});
System.out.println(result[0] + ", " + result[1]);   // 1, 7
```

#### Option 2: Return a Record (Java 16+ — Recommended)

```java
public record MinMax(int min, int max) {}

public static MinMax minMax(int[] arr) {
    int min = Integer.MAX_VALUE, max = Integer.MIN_VALUE;
    for (int n : arr) {
        min = Math.min(min, n);
        max = Math.max(max, n);
    }
    return new MinMax(min, max);
}

MinMax result = minMax(new int[]{3, 1, 7, 2});
System.out.println(result.min() + ", " + result.max());   // 1, 7
```

#### Option 3: Return a Map.Entry (Quick Pair)

```java
public static Map.Entry<String, Integer> findLongest(String[] words) {
    String longest = "";
    for (String w : words) if (w.length() > longest.length()) longest = w;
    return Map.entry(longest, longest.length());
}

var result = findLongest(new String[]{"hi", "hello", "hey"});
System.out.println(result.getKey() + " = " + result.getValue());   // hello = 5
```

#### Option 4: Mutate an Object Passed In (Side Effect)

```java
public static void compute(int[] input, List<Integer> output) {
    for (int n : input) {
        output.add(n * n);   // "return" values by adding to the passed collection
    }
}

List<Integer> squares = new ArrayList<>();
compute(new int[]{1, 2, 3}, squares);
System.out.println(squares);   // [1, 4, 9]
```

**C# comparison:** C# has `out` parameters, tuples `(int min, int max)`, and `ref` returns. Java has none of these — you must return objects.

### Method Overloading

Same method name, different parameter lists. The compiler picks the correct version based on arguments at compile time (static dispatch):

```java
public class Calculator {
    public int add(int a, int b) {
        return a + b;
    }

    public double add(double a, double b) {   // different parameter types
        return a + b;
    }

    public int add(int a, int b, int c) {     // different number of parameters
        return a + b + c;
    }
}

Calculator calc = new Calculator();
calc.add(1, 2);         // calls add(int, int) → 3
calc.add(1.5, 2.5);    // calls add(double, double) → 4.0
calc.add(1, 2, 3);     // calls add(int, int, int) → 6
```

**Rules:**
- Different parameter types or count — valid overload
- Different return type alone — NOT a valid overload (compile error)
- Different parameter names alone — NOT a valid overload

```java
public int add(int a, int b) { return a + b; }
public double add(int a, int b) { return a + b; }   // ❌ compile error — same params, only return differs
```

### Method Overriding

Subclass provides a new implementation for a method inherited from the superclass. The correct version is chosen at runtime based on the actual object type (dynamic dispatch / polymorphism):

```java
public class Animal {
    public String speak() {
        return "...";
    }
}

public class Dog extends Animal {
    @Override                        // annotation — compiler verifies this actually overrides
    public String speak() {
        return "Woof!";
    }
}

public class Cat extends Animal {
    @Override
    public String speak() {
        return "Meow!";
    }
}

Animal a = new Dog();    // reference type = Animal, actual type = Dog
a.speak();               // "Woof!" — calls Dog's version (runtime polymorphism)

Animal b = new Cat();
b.speak();               // "Meow!" — calls Cat's version
```

**Overriding rules:**
- Same method name, same parameters, same or covariant return type
- Access modifier can be same or wider (protected → public ✓, public → private ✗)
- Cannot override `final`, `static`, or `private` methods
- `@Override` annotation is optional but strongly recommended (catches typos)

---
### Method Hiding (Static Methods)

When a subclass defines a `static` method with the same signature as the parent, it **hides** (not overrides) the parent method. The version called depends on the reference type, not the object type:

```java
public class Parent {
    public static void greet() {
        System.out.println("Hello from Parent");
    }

    public void instanceGreet() {
        System.out.println("Instance: Parent");
    }
}

public class Child extends Parent {
    public static void greet() {          // HIDES Parent.greet() — no @Override
        System.out.println("Hello from Child");
    }

    @Override
    public void instanceGreet() {         // OVERRIDES — runtime polymorphism
        System.out.println("Instance: Child");
    }
}

Parent ref = new Child();
ref.greet();           // "Hello from Parent" — static: resolved by REFERENCE type
ref.instanceGreet();   // "Instance: Child"  — instance: resolved by OBJECT type
```

| | Overriding (Instance Methods) | Hiding (Static Methods) |
|--|-------------------------------|------------------------|
| Keyword | `@Override` | Same signature, no annotation |
| Dispatch | Runtime (object type) | Compile time (reference type) |
| Polymorphism | Yes | No |
| Which runs? | Actual object's version | Reference variable's type version |

### Varargs (Variable Arguments)

A method can accept a variable number of arguments using `...` syntax (like C#'s `params`):

```java
public static int sum(int... numbers) {   // numbers is actually an int[]
    int total = 0;
    for (int n : numbers) total += n;
    return total;
}

sum(1, 2);           // 3
sum(1, 2, 3, 4, 5); // 15
sum();               // 0 (empty array)
sum(new int[]{1, 2, 3});  // 6 (can also pass an array directly)
```

**Rules:**
- Only one varargs parameter per method
- Must be the last parameter: `void foo(String name, int... scores)` ✓
- `void foo(int... a, int... b)` ❌ — only one allowed

---
### Summary: Overloading vs Overriding vs Hiding

| | Overloading | Overriding | Hiding |
|--|-------------|-----------|--------|
| Same name? | Yes | Yes | Yes |
| Same params? | No (must differ) | Yes (must match) | Yes (must match) |
| Where? | Same class or parent/child | Subclass redefines parent's instance method | Subclass redefines parent's static method |
| Resolved at | Compile time | Runtime | Compile time |
| Annotation | None | `@Override` | None |
| `static`? | Can be static or instance | Instance methods only | Static methods only |
