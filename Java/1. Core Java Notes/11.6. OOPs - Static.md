### Static Members

`static` means the member belongs to the **class itself**, not to any particular instance. There's only one copy shared across all objects.

#### Static Fields (Class Variables)

```java
public class Employee {
    private String name;
    private static int employeeCount = 0;   // shared across ALL instances

    public Employee(String name) {
        this.name = name;
        employeeCount++;   // every new Employee increments the SAME counter
    }

    public static int getEmployeeCount() {
        return employeeCount;
    }
}

Employee a = new Employee("Alice");   // employeeCount = 1
Employee b = new Employee("Bob");     // employeeCount = 2
Employee.getEmployeeCount();          // 2 — accessed via class name, not instance
```

```
Instance fields (each object has its own copy):
┌─────────────┐  ┌─────────────┐
│ Employee a  │  │ Employee b  │
│ name="Alice"│  │ name="Bob"  │
└─────────────┘  └─────────────┘

Static field (one copy in the class, shared by all):
┌──────────────────────────────┐
│ Employee.class               │
│ employeeCount = 2            │  ← ALL instances share this
└──────────────────────────────┘
```

#### Static Methods

Cannot access instance fields or `this` — they have no object context:

```java
public class MathUtils {
    public static final double TAX_RATE = 0.08;

    // Static method — called on the CLASS, not an object
    public static double calculateTax(double amount) {
        return amount * TAX_RATE;
    }

    // ❌ This won't compile in a static method:
    // public static void broken() {
    //     System.out.println(this);   // error: 'this' doesn't exist in static context
    //     instanceMethod();           // error: can't call instance method without an object
    // }
}

// Usage — no instance needed
double tax = MathUtils.calculateTax(100.0);
```

**When to use static methods:**
- Utility/helper methods that don't need object state (`Math.sqrt()`, `Integer.parseInt()`)
- Factory methods (`List.of()`, `Map.entry()`)
- The `main()` method (JVM calls it without creating an instance)

#### Static Initializer Block (Static Constructor)

Runs once when the class is first loaded by the JVM — before any objects are created:

```java
public class Config {
    private static Map<String, String> settings;

    // Runs ONCE when class is first loaded
    static {
        settings = new HashMap<>();
        settings.put("env", "production");
        settings.put("version", "2.1");
        System.out.println("Config loaded!");
    }
}

// "Config loaded!" prints the first time any code references Config class
```

Multiple static blocks execute in order of appearance. Used for complex static initialization that can't be done in a one-liner.

#### Static Import

Use static members without qualifying with the class name:

```java
import static java.lang.Math.PI;
import static java.lang.Math.sqrt;
import static java.util.Collections.emptyList;

double r = sqrt(PI);              // instead of Math.sqrt(Math.PI)
List<String> empty = emptyList(); // instead of Collections.emptyList()
```

#### Where Are Static Members Stored?

Static members live in **Metaspace** (class metadata area), not on the heap with regular objects:

```
┌────────── HEAP ──────────────────────────────────┐
│  ┌──────────────┐  ┌──────────────┐             │
│  │ Employee a   │  │ Employee b   │  ← instances│
│  │ name="Alice" │  │ name="Bob"   │             │
│  └──────────────┘  └──────────────┘             │
└──────────────────────────────────────────────────┘

┌────────── METASPACE ─────────────────────────────┐
│  ┌────────────────────────────────────────┐      │
│  │ Employee.class (Klass metadata)        │      │
│  │                                        │      │
│  │  Static fields:                        │      │
│  │    employeeCount = 2  (value here)     │      │
│  │    COMPANY → ref ──────► (heap object) │      │
│  │                                        │      │
│  │  Method table (vtable):                │      │
│  │    getEmployeeCount() → bytecode       │      │
│  └────────────────────────────────────────┘      │
└──────────────────────────────────────────────────┘
```

- Static primitives (`static int count`) — value stored directly in Metaspace
- Static references (`static String NAME`) — pointer in Metaspace, actual object on heap
- Before Java 8, this was in PermGen (fixed size). Metaspace uses native memory and grows dynamically.

#### Why Can't We Have a Top-Level `static` Class?

`static` means "no reference to an enclosing instance." A top-level class has **no enclosing instance** to begin with — it's already independent. Marking it `static` would add no information:

```java
static class Person { }   // ❌ compile error: modifier 'static' not allowed here
```

But for a **nested class**, `static` makes sense — it removes the hidden reference to the outer instance:

```java
public class Outer {
    private int x = 10;

    // Non-static inner class — secretly holds Outer.this reference
    class Inner {
        void show() { System.out.println(x); }   // ✓ accesses Outer's field
    }

    // Static nested class — NO outer reference, fully independent
    static class StaticNested {
        void show() { /* can't access x — no Outer instance */ }
    }
}

Outer outer = new Outer();
Outer.Inner inner = outer.new Inner();                // needs an Outer instance
Outer.StaticNested nested = new Outer.StaticNested(); // no Outer instance needed
```

| Class type | Has enclosing instance? | `static` makes sense? |
|-----------|:-:|:-:|
| Top-level class | No (nothing encloses it) | No — already independent |
| Non-static inner class | Yes (`Outer.this`) | — |
| Static nested class | No (removed by `static`) | Yes — explicitly removes it |

**C# comparison:** In C#, `static class` means "can't be instantiated, all members must be static." Java has no equivalent — use `final` class + private constructor instead.

#### What `static` Can Apply To

| Element | Meaning |
|---------|---------|
| Field | One copy per class (not per instance) |
| Method | Called on class, no `this` access |
| Nested class | No reference to enclosing instance |
| Initializer block | Runs once when class loads |
| Import | Import static members directly |

**C# comparison:** Same concept. C#'s `static class` (can't be instantiated) doesn't exist in Java — use a private constructor + all static members instead.

#### Static and Inheritance — Method Hiding vs Overriding

Static methods are **not** polymorphic. When a subclass defines a static method with the same signature as the parent, it **hides** the parent method rather than overriding it. The version called depends on the **reference type**, not the runtime object type:

```java
class Animal {
    public static void speak() {
        System.out.println("Animal speaks");
    }

    public void eat() {
        System.out.println("Animal eats");
    }
}

class Dog extends Animal {
    public static void speak() {   // HIDES Animal.speak()
        System.out.println("Dog barks");
    }

    @Override
    public void eat() {            // OVERRIDES Animal.eat()
        System.out.println("Dog eats kibble");
    }
}

Animal ref = new Dog();
ref.speak();   // "Animal speaks" — static: resolved by reference type (Animal)
ref.eat();     // "Dog eats kibble" — instance: resolved by object type (Dog)
```

| | Instance methods (overriding) | Static methods (hiding) |
|--|:--:|:--:|
| Resolved at | Runtime (dynamic dispatch) | Compile time (reference type) |
| `@Override` | Yes — compiler checks | No — not overriding, just hiding |
| Polymorphism | Yes | No |

**Key takeaway:** Static methods belong to the class, not the object — so the JVM doesn't look at the actual object type at runtime.

#### Accessing Static Members via Instance References

Java allows calling static members through an instance reference, but this is misleading and discouraged:

```java
Employee emp = new Employee("Alice");
int count = emp.getEmployeeCount();       // ⚠️ compiles but misleading
int count2 = Employee.getEmployeeCount(); // ✓ clear — called on the class
```

The compiler silently replaces `emp.getEmployeeCount()` with `Employee.getEmployeeCount()`. The instance is ignored — even `null` works:

```java
Employee nullRef = null;
nullRef.getEmployeeCount();   // no NullPointerException! Static call ignores the reference.
```

Most IDEs and linters (SpotBugs, SonarQube) flag this as a warning. Always use the class name.

#### Static Members and Serialization

Static fields are **not serialized**. They belong to the class, not the object, so they're excluded from the serialization stream:

```java
public class GameState implements Serializable {
    private int playerScore;           // ✓ serialized
    private static int highScore = 0;  // ✗ NOT serialized — belongs to the class

    public GameState(int score) {
        this.playerScore = score;
        if (score > highScore) highScore = score;
    }
}

// Save
GameState state = new GameState(500);   // highScore = 500
objectOutputStream.writeObject(state);

// In a new JVM — highScore resets to 0 (default), playerScore is restored to 500
GameState restored = (GameState) objectInputStream.readObject();
```

If you need to persist a static value, serialize it manually or store it externally.

#### Why Is `main()` Static?

The `main` method is the entry point of a Java program. The JVM needs to call it **before any objects exist**. Since instance methods require an object, and no object has been created yet at startup, `main` must be `static`:

```java
public class App {
    public static void main(String[] args) {
        // JVM calls this directly on the class — no `new App()` needed
        System.out.println("Hello");
    }
}
```

If `main` were not static, the JVM would need to instantiate the class first — but which constructor should it call? What if the constructor needs arguments? Making it `static` avoids this chicken-and-egg problem entirely.

#### Common Pitfalls with `static`

| Pitfall | Problem | Fix |
|---------|---------|-----|
| Mutable static state | Shared across all instances and threads — race conditions | Use synchronization, `AtomicInteger`, or avoid mutable statics |
| Static collections growing forever | Memory leak — objects stay reachable via the static reference | Use weak references, bounded caches, or clear on shutdown |
| Static method calling instance method | Won't compile — no `this` in static context | Create an instance first, or make the method static |
| Testing difficulties | Static state carries over between tests | Reset static state in `@BeforeEach` / `@AfterEach`, or prefer instance methods |
| Tight coupling | Callers depend on the concrete class name | For testability, prefer dependency injection over static utility methods |

```java
// ❌ Mutable static — dangerous in multi-threaded code
public class Registry {
    private static List<String> entries = new ArrayList<>();  // shared, unsynchronized

    public static void register(String entry) {
        entries.add(entry);   // race condition if called from multiple threads
    }
}

// ✓ Thread-safe alternative
public class Registry {
    private static final List<String> entries = Collections.synchronizedList(new ArrayList<>());

    public static void register(String entry) {
        entries.add(entry);   // synchronized
    }
}
```
