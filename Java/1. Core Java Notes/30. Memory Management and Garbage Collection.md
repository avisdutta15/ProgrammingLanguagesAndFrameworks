# 33. Memory Management and Garbage Collection

### Memory Model

```
JVM Memory
├── Heap (shared across threads)
│   ├── Young Generation
│   │   ├── Eden Space (new objects created here)
│   │   ├── Survivor Space S0
│   │   └── Survivor Space S1
│   └── Old Generation (long-lived objects)
├── Metaspace (class metadata — replaced PermGen in Java 8)
├── Stack (per thread — local variables, method calls)
└── Native Memory (direct buffers, JNI)
```

### Garbage Collectors

| GC | Use Case | Flag |
|----|----------|------|
| G1 GC | Default since Java 9. General purpose, low latency | `-XX:+UseG1GC` |
| ZGC | Ultra-low latency (<1ms pauses). Large heaps | `-XX:+UseZGC` |
| Shenandoah | Low latency, concurrent | `-XX:+UseShenandoahGC` |
| Parallel GC | High throughput, batch processing | `-XX:+UseParallelGC` |
| Serial GC | Small heaps, single-threaded | `-XX:+UseSerialGC` |

### Memory Management Best Practices

```java
// No manual memory management (no Dispose pattern needed for memory)
// But resources still need explicit closing (try-with-resources)

// Weak references (like C# WeakReference)
WeakReference<HeavyObject> weakRef = new WeakReference<>(heavyObject);
HeavyObject obj = weakRef.get();  // may return null if GC'd

// Soft references (cleared only under memory pressure)
SoftReference<byte[]> cache = new SoftReference<>(data);

// Phantom references (for cleanup callbacks)
PhantomReference<Object> phantom = new PhantomReference<>(obj, queue);

// Cleaner API (Java 9+) — replacement for finalize()
Cleaner cleaner = Cleaner.create();
cleaner.register(this, () -> {
    // cleanup action — runs when object becomes phantom reachable
});
```

### JVM Tuning Flags

```bash
-Xms512m          # Initial heap size
-Xmx4g            # Maximum heap size
-XX:+PrintGCDetails    # GC logging
-XX:MaxMetaspaceSize=256m
-XX:+HeapDumpOnOutOfMemoryError
```
