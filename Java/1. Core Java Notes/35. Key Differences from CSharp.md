# 38. Key Differences from C#

This section consolidates the most important mental model shifts for a C# developer learning Java.

### Things Java Does NOT Have

| C# Feature | Java Equivalent / Workaround |
|-------------|------------------------------|
| Properties (`get; set;`) | Getter/setter methods or Records |
| `async` / `await` | CompletableFuture or Virtual Threads |
| LINQ query syntax | Streams API |
| Extension methods | Utility classes with static methods |
| `struct` (value types) | Everything is a reference type (except primitives) |
| Nullable reference types (`?`) | `Optional<T>` for return types |
| `decimal` type | `BigDecimal` |
| Operator overloading | Not supported |
| Indexers (`this[int]`) | `.get(int)` methods |
| Events / delegates | Functional interfaces + listener pattern |
| `nameof()` | No equivalent (use strings or reflection) |
| `out` / `ref` parameters | Return objects or use holder classes |
| Tuples (`(int, string)`) | Records, or `Map.Entry`, or custom classes |
| `dynamic` type | No equivalent (reflection only) |
| `default` interface implementation on fields | Not possible |
| String interpolation `$"..."` | `"...".formatted(...)` or `STR."..."` (preview) |
| `using` (disposal) | `try-with-resources` |
| `yield return` (iterators) | No direct equivalent (use Streams or Iterators) |
| Unsigned integer types | Not available |
| Multi-dimensional arrays `[,]` | Array of arrays `[][]` only |
| Partial classes | Not available |
| `init`-only properties | Not available (use records or builder pattern) |

### Things Java Has That C# Doesn't

| Java Feature | Notes |
|--------------|-------|
| Checked exceptions | Must catch or declare — love it or hate it |
| Package-private (default) access | No keyword — accessible within package |
| Labeled breaks/continues | Break out of nested loops by label |
| Enum classes with methods | Enums are full objects with behavior |
| Type erasure (generics) | No runtime generic type info |
| `>>>` unsigned right shift | Dedicated operator |
| Text blocks (`"""..."""`) | Available since Java 15 (C# got raw strings in 11) |
| `final` local variables | Method params can be final |
| Strong module system (JPMS) | Explicit dependency declarations |
| Virtual Threads | Lightweight concurrency without colored functions |

### Syntax Quick Reference

| Concept | C# | Java |
|---------|-----|------|
| Inherit class | `: BaseClass` | `extends BaseClass` |
| Implement interface | `: IInterface` | `implements Interface` |
| Call base constructor | `: base(args)` | `super(args)` first line |
| Call base method | `base.Method()` | `super.method()` |
| Prevent override | `sealed` method | `final` method |
| Prevent inheritance | `sealed` class | `final` class |
| Abstract method | `abstract void M();` | `abstract void m();` |
| Constant | `const` or `readonly` | `static final` |
| Type check | `obj is Type t` | `obj instanceof Type t` |
| Null coalescing | `x ?? default` | `Optional.orElse(default)` |
| Null conditional | `x?.Method()` | `if (x != null) x.method()` |
| String interpolation | `$"Hello {name}"` | `"Hello %s".formatted(name)` |
| Array length | `arr.Length` | `arr.length` |
| Collection count | `list.Count` | `list.size()` |
| Print | `Console.WriteLine()` | `System.out.println()` |
| Main method | `static void Main(string[] args)` | `public static void main(String[] args)` |
| Package/namespace | `namespace X.Y { }` | `package x.y;` (one per file, matches directory) |
| Discard | `_ = expression` | No direct equivalent |
| Object initializer | `new Foo { X = 1 }` | No equivalent (use builder or constructor) |
| Collection initializer | `new List<int> { 1, 2, 3 }` | `List.of(1, 2, 3)` or `new ArrayList<>(List.of(...))` |

### File and Project Structure Differences

| C# | Java |
|----|------|
| One `.csproj` per project | One `pom.xml` or `build.gradle` |
| Namespace ≠ directory (but convention) | Package = directory structure (enforced) |
| Multiple classes per file | One public class per file (enforced) |
| Solution (`.sln`) groups projects | Multi-module Maven/Gradle project |
| NuGet packages | Maven Central / Gradle dependencies |
| `bin/Debug/net8.0/` | `target/` (Maven) or `build/` (Gradle) |

### Philosophy Differences

1. **Convention over configuration** — Java frameworks (Spring) rely heavily on conventions and annotations, similar to ASP.NET Core but more annotation-driven.

2. **Interfaces over inheritance** — Java ecosystem favors composition and interfaces even more than C#. "Program to an interface" is deeply ingrained.

3. **Immutability emphasis** — Modern Java strongly favors immutable objects (records, `List.of()`, `Map.of()`). Mutability is the exception.

4. **No properties** — This is the biggest daily friction point. You'll write `getName()` and `setName()` constantly. Use Records for data classes, or Lombok `@Data` annotation for boilerplate reduction.

5. **Ecosystem maturity** — Java's ecosystem is older and larger. For almost any problem, there's a well-established library (often multiple competing ones).
