# 15. Encapsulation and Access Modifiers

### Access Modifiers

| Modifier | Class | Package | Subclass | World |
|----------|-------|---------|----------|-------|
| `public` | ✓ | ✓ | ✓ | ✓ |
| `protected` | ✓ | ✓ | ✓ | ✗ |
| (default/package-private) | ✓ | ✓ | ✗ | ✗ |
| `private` | ✓ | ✗ | ✗ | ✗ |

**Key difference from C#:** Java has a "package-private" default (no keyword) which gives access to all classes in the same package. C#'s `internal` is similar but scoped to assembly. Java has no direct equivalent of `internal`.

### Encapsulation Pattern (JavaBeans Convention)

```java
public class Account {
    private double balance;
    private String owner;

    // Getter
    public double getBalance() {
        return balance;
    }

    // Setter with validation
    public void setBalance(double balance) {
        if (balance < 0) throw new IllegalArgumentException("Balance cannot be negative");
        this.balance = balance;
    }

    // Boolean getter uses 'is' prefix
    private boolean active;
    public boolean isActive() {
        return active;
    }
}
```

### The final Keyword (Multiple Uses)

```java
// final variable — like 'readonly' in C# (for fields) or 'const' (for locals)
final int MAX = 100;             // constant (compile-time for primitives)
final List<String> items = new ArrayList<>();  // reference can't change, contents CAN

// final parameter
public void process(final String input) {
    // input = "other";  // compile error
}

// final field — must be set in constructor or declaration
private final String id;

// final method — cannot be overridden
// final class — cannot be extended
```
