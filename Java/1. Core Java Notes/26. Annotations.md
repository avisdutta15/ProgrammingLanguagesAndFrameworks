# 29. Annotations

Annotations are Java's equivalent of C# attributes — metadata attached to code elements. They provide a way to add information to your code that can be used by the compiler, build tools, frameworks, or your own code at runtime.

### How Annotations Work

```java
// Annotations start with @ followed by the annotation type name
@Override
public String toString() { return "Hello"; }

// Annotations can have elements (key-value pairs)
@SuppressWarnings(value = "unchecked")

// If there's only one element named "value", you can omit the name
@SuppressWarnings("unchecked")

// Multiple elements
@Deprecated(since = "2.0", forRemoval = true)

// Array values
@SuppressWarnings({"unchecked", "rawtypes"})

// Annotations with no elements (marker annotations)
@Override  // no parentheses needed
```

### Built-in Annotations

#### Compiler Annotations

```java
// @Override — compiler verifies this actually overrides something
@Override
public boolean equals(Object obj) { ... }
// If you misspell the method or get the signature wrong, compiler ERROR (not silent bug)

// @Deprecated — generates compiler warnings when used
@Deprecated
public void oldMethod() { }

@Deprecated(since = "11", forRemoval = true)  // Java 9+ — stronger signal
public void legacyMethod() { }
// Calling legacyMethod() produces: "warning: legacyMethod() in MyClass has been deprecated
//                                   and marked for removal"

// @SuppressWarnings — silence specific compiler warnings
@SuppressWarnings("unchecked")         // raw type usage
@SuppressWarnings("deprecation")       // deprecated API usage
@SuppressWarnings("serial")            // missing serialVersionUID
@SuppressWarnings({"unchecked", "rawtypes"})  // multiple

// @FunctionalInterface — compiler enforces exactly one abstract method
@FunctionalInterface
public interface Converter<F, T> {
    T convert(F from);
    // Adding another abstract method here → COMPILE ERROR
}

// @SafeVarargs — suppresses heap pollution warnings on varargs generics
@SafeVarargs
public final <T> List<T> asList(T... elements) {
    return List.of(elements);
}
```

#### Javadoc Annotations (in comments, not code)

```java
/**
 * Calculates compound interest.
 *
 * @param principal the initial amount
 * @param rate annual interest rate (0.05 = 5%)
 * @param years number of years
 * @return the final amount after compound interest
 * @throws IllegalArgumentException if principal is negative
 * @since 2.0
 * @see BigDecimal
 * @deprecated Use {@link #calculateInterest(BigDecimal, BigDecimal, int)} instead
 */
@Deprecated(since = "3.0")
public double calculateInterest(double principal, double rate, int years) { ... }
```

### Custom Annotations — Full Guide

#### Defining an Annotation

```java
import java.lang.annotation.*;

// @interface declares an annotation type (not a regular interface!)
public @interface MyAnnotation {
    // Elements look like methods but are really named parameters
    String value();                    // required (no default)
    int priority() default 0;         // optional (has default)
    String[] tags() default {};       // array with empty default
    Class<?> handler() default Void.class;  // Class type element
    RetryPolicy policy() default RetryPolicy.FIXED;  // enum element
}
```

#### Element Types Allowed

Annotation elements can only be:
- Primitives (`int`, `double`, `boolean`, etc.)
- `String`
- `Class<?>` or `Class<? extends SomeType>`
- Enum types
- Other annotation types
- Arrays of any of the above

**NOT allowed:** objects, collections, interfaces, `null` as default value.

#### Real-World Custom Annotation Examples

```java
// Validation annotation
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
public @interface NotEmpty {
    String message() default "Field must not be empty";
}

// Rate limiting annotation
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface RateLimit {
    int maxRequests() default 100;
    int windowSeconds() default 60;
    String key() default "";
}

// Caching annotation
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface Cacheable {
    String cacheName();
    long ttlSeconds() default 300;
    boolean refreshOnAccess() default false;
}

// Auditing annotation
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface Auditable {
    String action();
    String resource() default "";
}

// Usage
public class UserService {

    @RateLimit(maxRequests = 10, windowSeconds = 60)
    @Auditable(action = "CREATE", resource = "user")
    @Cacheable(cacheName = "users", ttlSeconds = 600)
    public User createUser(@NotEmpty String name, @NotEmpty String email) {
        // ...
    }
}
```

### Retention Policies — When Is the Annotation Available?

| Policy | Lifetime | Use Case |
|--------|----------|----------|
| `SOURCE` | Discarded during compilation | Compiler plugins, code generators, linting |
| `CLASS` | Stored in .class file, NOT available at runtime | Bytecode analysis tools, default if omitted |
| `RUNTIME` | Available via reflection at runtime | Frameworks (Spring, JUnit), custom processors |

```java
// SOURCE — only exists in source code
@Retention(RetentionPolicy.SOURCE)
public @interface Todo {
    String value();
    String assignee() default "";
}
// Use: custom linting tools scan source for @Todo annotations

// CLASS — available in bytecode but not reflection
@Retention(RetentionPolicy.CLASS)
public @interface NonNull { }
// Use: static analysis tools like SpotBugs/ErrorProne read from bytecode

// RUNTIME — the most common for frameworks
@Retention(RetentionPolicy.RUNTIME)
public @interface Transactional { }
// Use: Spring reads at runtime to wrap methods in transaction logic
```

### Target Element Types

```java
ElementType.TYPE              // class, interface, enum, record, annotation
ElementType.FIELD             // instance/static field
ElementType.METHOD            // method declaration
ElementType.PARAMETER         // method/constructor parameter
ElementType.CONSTRUCTOR       // constructor declaration
ElementType.LOCAL_VARIABLE    // local variable (SOURCE retention only — useless at runtime)
ElementType.ANNOTATION_TYPE   // meta-annotation (annotation on annotations)
ElementType.PACKAGE           // package-info.java declaration
ElementType.TYPE_PARAMETER    // generic type parameter: class Box<@NonNull T> (Java 8+)
ElementType.TYPE_USE          // any type use: (@NonNull String), new @Immutable Object() (Java 8+)
ElementType.RECORD_COMPONENT  // record component: record Point(@Positive int x) (Java 16+)
ElementType.MODULE            // module declaration (Java 9+)
```

```java
// TYPE_USE example — annotate ANY type usage
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE_USE)
public @interface NonNull { }

// Can now annotate anywhere a type appears:
@NonNull String name;
List<@NonNull String> items;
String @NonNull [] array;
Object value = (@NonNull String) obj;
```

### Meta-Annotations (Annotations on Annotations)

```java
// The 4 built-in meta-annotations:
@Retention(...)   // when is the annotation available?
@Target(...)      // where can it be applied?
@Documented       // should it appear in Javadoc?
@Inherited        // should subclasses inherit this annotation from parent class?

// @Inherited example
@Inherited
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
public @interface Audited { }

@Audited
public class BaseService { }

public class UserService extends BaseService { }
// UserService is also @Audited — inherited from BaseService
// Note: @Inherited only works on TYPE annotations, not methods or fields
```

### Repeatable Annotations (Java 8+)

```java
// Step 1: Define container annotation
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface Schedules {
    Schedule[] value();
}

// Step 2: Define repeatable annotation pointing to container
@Repeatable(Schedules.class)
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface Schedule {
    String cron();
    String zone() default "UTC";
}

// Step 3: Use it multiple times
@Schedule(cron = "0 0 * * *", zone = "US/Eastern")
@Schedule(cron = "0 12 * * *")
@Schedule(cron = "0 18 * * FRI")
public void runReports() { }
```

### Processing Annotations at Runtime (Reflection)

```java
// Reading annotations from a class
Class<?> clazz = UserService.class;

if (clazz.isAnnotationPresent(Audited.class)) {
    Audited audit = clazz.getAnnotation(Audited.class);
    System.out.println("Class is audited");
}

// Reading annotations from methods
for (Method method : clazz.getDeclaredMethods()) {
    if (method.isAnnotationPresent(RateLimit.class)) {
        RateLimit limit = method.getAnnotation(RateLimit.class);
        System.out.println(method.getName() + " limited to "
            + limit.maxRequests() + " requests per " + limit.windowSeconds() + "s");
    }

    // Repeatable annotations
    Schedule[] schedules = method.getAnnotationsByType(Schedule.class);
    for (Schedule s : schedules) {
        System.out.println("Scheduled: " + s.cron());
    }
}

// Reading annotations from fields
for (Field field : clazz.getDeclaredFields()) {
    if (field.isAnnotationPresent(NotEmpty.class)) {
        NotEmpty ne = field.getAnnotation(NotEmpty.class);
        // Validate the field is not empty...
    }
}

// Reading annotations from parameters
Method m = clazz.getMethod("createUser", String.class, String.class);
Parameter[] params = m.getParameters();
for (Parameter param : params) {
    if (param.isAnnotationPresent(NotEmpty.class)) {
        System.out.println(param.getName() + " must not be empty");
    }
}
```

### Building a Simple Annotation Processor (Runtime)

```java
// A mini validation framework using annotations

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
public @interface Min {
    int value();
    String message() default "Value is below minimum";
}

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
public @interface Max {
    int value();
    String message() default "Value exceeds maximum";
}

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
public @interface NotNull {
    String message() default "Field must not be null";
}

// The validator
public class Validator {
    public static List<String> validate(Object obj) {
        List<String> errors = new ArrayList<>();
        for (Field field : obj.getClass().getDeclaredFields()) {
            field.setAccessible(true);
            try {
                Object value = field.get(obj);

                if (field.isAnnotationPresent(NotNull.class) && value == null) {
                    errors.add(field.getAnnotation(NotNull.class).message());
                }

                if (field.isAnnotationPresent(Min.class) && value instanceof Number n) {
                    Min min = field.getAnnotation(Min.class);
                    if (n.intValue() < min.value()) {
                        errors.add(min.message() + " (min: " + min.value() + ")");
                    }
                }

                if (field.isAnnotationPresent(Max.class) && value instanceof Number n) {
                    Max max = field.getAnnotation(Max.class);
                    if (n.intValue() > max.value()) {
                        errors.add(max.message() + " (max: " + max.value() + ")");
                    }
                }
            } catch (IllegalAccessException e) {
                throw new RuntimeException(e);
            }
        }
        return errors;
    }
}

// Model using validation annotations
public class CreateOrderRequest {
    @NotNull(message = "Customer ID is required")
    private String customerId;

    @Min(value = 1, message = "Quantity must be at least 1")
    @Max(value = 1000, message = "Quantity cannot exceed 1000")
    private int quantity;

    @Min(value = 0, message = "Price cannot be negative")
    private double price;
}

// Usage
CreateOrderRequest request = new CreateOrderRequest();
List<String> errors = Validator.validate(request);
// ["Customer ID is required", "Quantity must be at least 1"]
```

### Annotations in Frameworks — Common Patterns

#### Spring Framework

```java
@RestController                         // marks class as HTTP controller
@RequestMapping("/api/users")           // base URL path
public class UserController {

    @Autowired                          // dependency injection
    private UserService userService;

    @GetMapping("/{id}")                // HTTP GET handler
    @ResponseStatus(HttpStatus.OK)
    public User getUser(@PathVariable Long id) {
        return userService.findById(id);
    }

    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    @Transactional                      // wrap in database transaction
    public User createUser(@RequestBody @Valid CreateUserDto dto) {
        return userService.create(dto);
    }
}

@Service                                // marks as Spring-managed bean
@Slf4j                                  // Lombok: generates logger field
public class UserService {

    @Value("${app.max-users}")          // inject config property
    private int maxUsers;

    @Cacheable("users")                 // cache method results
    public User findById(Long id) { ... }

    @Scheduled(fixedRate = 60000)       // run every 60 seconds
    public void cleanupExpired() { ... }

    @EventListener                      // react to application events
    public void onUserCreated(UserCreatedEvent event) { ... }
}
```

### C# Attribute Comparison

| C# Attribute | Java Annotation Equivalent |
|--------------|---------------------------|
| `[Obsolete]` | `@Deprecated` |
| `[Serializable]` | `implements Serializable` (marker interface, not annotation) |
| `[Required]` | `@NotNull` (Bean Validation) |
| `[Range(1, 100)]` | `@Min(1) @Max(100)` |
| `[HttpGet("/path")]` | `@GetMapping("/path")` (Spring) |
| `[Authorize]` | `@PreAuthorize(...)` or `@Secured(...)` (Spring Security) |
| `[TestMethod]` / `[Fact]` | `@Test` |
| `[AttributeUsage(...)]` | `@Target(...)` |
| Custom `[MyAttr]` | Custom `@MyAnnotation` |

**Key differences from C# attributes:**
- Java annotations use `@interface` to define (C# uses classes inheriting `Attribute`)
- Java has retention policies controlling lifetime (C# attributes always available at runtime)
- Java's `@Inherited` propagates to subclasses (C# uses `Inherited = true` in `[AttributeUsage]`)
- Java annotations cannot have complex constructors — only simple element declarations
- Java's annotation processing (APT) is more powerful than C#'s source generators for compile-time code gen
