# 20. Generics

Java generics are similar in syntax to C# generics but very different under the hood due to **type erasure**.

### Basic Generics

```java
// Generic class
public class Box<T> {
    private T content;

    public void set(T content) { this.content = content; }
    public T get() { return content; }
}

// Generic method
public <T> T firstOrNull(List<T> list) {
    return list.isEmpty() ? null : list.get(0);
}

// Multiple type parameters
public class Pair<K, V> {
    private final K key;
    private final V value;

    public Pair(K key, V value) {
        this.key = key;
        this.value = value;
    }
}
```

### Bounded Type Parameters

```java
// Upper bound (like 'where T : IComparable' in C#)
public <T extends Comparable<T>> T max(T a, T b) {
    return a.compareTo(b) >= 0 ? a : b;
}

// Multiple bounds (& not ,)
public <T extends Serializable & Comparable<T>> void process(T item) { }

// Note: only ONE class bound allowed, must come first; multiple interface bounds are fine
public <T extends Number & Comparable<T> & Serializable> void handle(T item) { }
```

### Wildcards (No C# Equivalent!)

```java
// Unbounded wildcard — "any type"
public void printList(List<?> list) {
    for (Object item : list) {
        System.out.println(item);
    }
}

// Upper-bounded wildcard — "? extends" = covariance (like C# 'out')
public double sum(List<? extends Number> numbers) {
    double total = 0;
    for (Number n : numbers) {
        total += n.doubleValue();
    }
    return total;
}
// Can read as Number, but CANNOT add to the list

// Lower-bounded wildcard — "? super" = contravariance (like C# 'in')
public void addNumbers(List<? super Integer> list) {
    list.add(1);
    list.add(2);
    list.add(3);
}
// Can add Integer, but reading gives only Object
```

### PECS Principle: Producer Extends, Consumer Super

```java
// If you READ from a structure → use extends (producer)
// If you WRITE to a structure → use super (consumer)
// If both → use exact type

public <T> void copy(List<? extends T> source, List<? super T> destination) {
    for (T item : source) {
        destination.add(item);
    }
}
```

### Type Erasure (Critical Difference from C#!)

Java generics are implemented via **type erasure** — generic type information is removed at compile time.

```java
// At runtime, these are the SAME class:
List<String> strings = new ArrayList<>();
List<Integer> ints = new ArrayList<>();
strings.getClass() == ints.getClass()  // true!

// Consequences:
// 1. Cannot create generic arrays
T[] array = new T[10];  // COMPILE ERROR

// 2. Cannot use instanceof with generic types
if (obj instanceof List<String>) { }  // COMPILE ERROR
if (obj instanceof List<?>) { }       // OK (unbounded wildcard)

// 3. Cannot use primitive types as type arguments
List<int> nums;     // COMPILE ERROR — must use List<Integer>

// 4. Cannot create instances of type parameters
T instance = new T();  // COMPILE ERROR
```

**C# comparison:** C# has reified generics — type info is preserved at runtime. `typeof(List<int>) != typeof(List<string>)`. You CAN use `new T()` with constraints. Java cannot do any of this.
